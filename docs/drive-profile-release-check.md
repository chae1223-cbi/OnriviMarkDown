# Drive 사용자 서식 수정 배포 확인

## 검증된 수정

- 환경설정의 cloud 리소스 폴더 ID를 유지한다. 이름이 변경되어도 같은 ID를 사용한다.
- 사용자 서식이 없다는 이유로 다른 Drive 폴더를 자동 선택하지 않는다.
- 선택한 폴더의 profiles/userCssProfiles.json만 읽는다.
- 유효한 토큰이 있으면 재로그인 없이 다시 읽는다. 실제 읽기가 끝난 뒤 성공을 표시한다.
- 환경설정에 Drive 폴더 경로, ID, Drive에서 열기 링크를 표시한다.

## 확인 결과

- 제공한 userCssProfiles (3).json: 시스템 7개, 사용자 2개(연습테스트, 소형책 출판 전문 서식).
- 해당 파일을 실제 읽기 및 정규화 코드에 적용해 두 사용자 서식 유지 확인.
- 폴더 복원, 위치 표시, 다시 읽기 테스트 통과.
- 타입 검사와 로컬 스냅샷 웹 빌드 통과.
- 운영 Cloudflare 설정과 실제 사용자 화면은 아직 확인하지 않았다.

## 기존 배포 흐름

블로그 발행 API가 Supabase에 변경을 저장한 뒤 CLOUDFLARE_PAGES_DEPLOY_HOOK을 호출한다.
Cloudflare는 연결된 저장소 코드로 빌드한다. 훅 호출만으로 로컬의 미커밋 수정이 반영되지는 않는다.
운영 Function에는 HYPERDRIVE 바인딩이 설정돼 있다. 빌드 스냅샷은 Cloudflare 빌드 환경의 DATABASE_URL 또는 BLOG_DATABASE_URL을 사용한다.
로컬에 DB 주소가 없다는 사실로 Cloudflare 설정 누락을 판단하지 않는다.
BLOG_USE_LOCAL_SNAPSHOT=1로 만든 로컬 검증 결과물은 운영 배포에 사용하지 않는다.

## 배포 후 확인

1. 코드가 Cloudflare에 연결된 저장소/브랜치에 반영됐는지 확인한다.
2. Cloudflare의 해당 커밋 빌드가 성공했는지 확인한다.
3. Onrivi 환경설정에서 리소스 폴더 ID를 실제 사용자 JSON이 있는 폴더와 비교한다.
4. 내 서식에서 다시 읽기를 실행한다. 연습테스트와 소형책 출판 전문 서식이 표시돼야 한다.
5. Drive 연결을 끊고 다시 연결한 뒤 동일 폴더 ID와 두 서식이 유지되는지 확인한다.

현재 작업 트리에는 앞선 리소스 기능 변경도 함께 있다. 배포할 변경 범위를 확인한 뒤 커밋한다.
