# HWP 신청서 가져오기 품질 개선 계획

기준 문서: `붙임. 2026년 예비창업패키지 특화분야(소셜벤처) 창업준비 아카데미 참여신청서_이름.hwp`의 2026-10-26 온리비 가져오기 결과와 KORDOC `parse_document` 결과. 원본 신청서 파일은 저장소에 추가하지 않는다.

## 반영 상태 (2026-10-26)

- 완료: 제어문자 제거, 긴 장식 글리프 축약, HWP 병합 셀의 `colspan`·`rowspan` 보존, 셀 안 표 보존, 동의 체크박스 레이블 개선.
- 검증: 위 신청서로 가져오기 회귀 스크립트를 실행해 본문, 병합·중첩 표, 체크박스 6개, 이미지 링크를 확인했다. DOCX/HWPX 표 및 HWP 스트림 검사도 통과했다.
- 남은 확인: 실제 온리비 화면에서 이미지의 저장·재열기 동작, 양자택일 항목의 동시 선택 방지, 지식 보관함 청크와 원본 위치 연결. 인쇄 레이아웃 재현은 범위 밖이다.

## 확인된 차이

| 우선순위 | 온리비 결과 | 기대 결과 | 관련 코드 |
| --- | --- | --- | --- |
| P0 | `□ 일반현황\u001f`처럼 U+001F 제어문자가 제목에 남음 | HWP 제어문자를 텍스트로 출력하지 않고 필요한 공백·줄바꿈만 복원 | `frontend/src/lib/fileImporter.ts`의 `HWPChar` 처리, `frontend/src/lib/hwpStreams.ts` |

| P1 | 신청자 소개의 셀 안 표가 일반 텍스트로 풀리고, 개인정보 동의서는 제목 표와 본문이 분리됨 | 셀 안 표와 상위 표의 관계를 유지하거나 원본 구조를 설명하는 대체 표현 제공 | HWP 재귀 추출 및 표 직렬화 |

KORDOC도 모든 복잡한 표를 원본 화면처럼 재현하지는 않는다. 이 계획의 목표는 **편집·검색 가능한 내용과 표의 논리 구조**를 보존하는 것이다. 인쇄 레이아웃의 완전한 복제는 목표에 포함하지 않는다.

## 작업 순서

1. **재현 기준 고정:** 같은 HWP를 온리비에서 다시 가져와 본문·표·이미지·체크박스 결과를 기록한다. 저장소 회귀 테스트에는 개인 신청서 대신 동일 구조의 비식별 합성 HWP 또는 파서 객체 fixture를 사용한다.
2. **문자 정규화:** `HWPChar`의 문자열 값과 복구 파서 출력에서 C0 제어문자를 처리한다. U+001F는 제거 또는 문맥에 맞는 공백으로 치환한다. 반복 장식선은 패턴과 길이를 확인해 정규화하며 모든 사설영역 문자를 일괄 삭제하지 않는다.
3. **표 구조 보존:** HWP 파서가 노출하는 셀 좌표·행/열 병합 크기를 확인하고 중간 표 모델에 담는다. 단순 표는 GFM 파이프 표로, 병합·중첩 표는 안전한 HTML 표로 출력한다. 기존 `importHtmlMarkdown.ts`의 HTML 표 보존 정책을 재사용하거나 공통 직렬화기로 합친다.
4. **양식 요소 보존:** 체크박스의 상태·레이블·그룹을 문맥과 함께 직렬화하고, 제목에 쓰인 `□`는 체크박스로 변환하지 않는다. 이미지 링크의 미리보기·저장·재열기 동작을 확인한다.
5. **지식 보관함 연결:** 구조화된 표와 원본 위치를 청크에 전달한다. 이 단계는 [다음 주 문서 청킹 작업](../ROADMAP.md)과 함께 진행한다.

## 완료 기준

- 이번 문서의 `신청자명 = 000`, 모든 사업·기술 분야 항목, 신청자 소개 4개 항목, 두 개인정보 동의서의 핵심 문구가 누락 없이 나온다.
- 결과 본문에 U+001F 등 출력 불가 제어문자와 긴 장식 글리프 반복이 없다. `□` 항목 부호와 6개의 선택 체크박스는 구분된다.
- 병합 셀은 `colspan`·`rowspan` 또는 동등한 구조 정보로 표현되고, 셀 안 표의 관계가 유지된다. 표를 평탄화해야 하는 경우 사용자에게 구조 손실을 알린다.
- 추출된 이미지가 가져오기 직후와 저장·재열기 후 모두 보인다.
- 합성 fixture의 가져오기 결과를 기존 DOCX·HWPX 표 테스트와 함께 검증하고, 문서 내용의 검색 청크에서 표와 출처를 확인한다.
