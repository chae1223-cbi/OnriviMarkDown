# 코드블록 개선 구현계획서

작성일: 2026-10-05

## 1. 목적과 범위

첨부된 6개 화면과 현재 소스를 대조하여 편집기의 선택 표시, 코드블록 헤더의 제목 유실, 미리보기의 불필요한 행 간격을 개선한다. 웹과 데스크탑에 같은 동작을 적용하며, HTML/PDF/EPUB/HWPX 내보내기와 HTML/EPUB 가져오기의 코드블록 보존을 회귀 검증한다.

문의 화면의 ‘완료됨’ 상태는 결함이 해결되었다는 기술적 증거로 사용하지 않는다. 아래 구현·검증 기록을 기준으로 현재 상태를 판단한다.

## 구현·검증 기록

- 전체 fence 정보와 원본 코드 텍스트를 Markdown AST에서 보존한다. 공백 포함 제목 및 언어+제목을 분리하고 빈/한 줄 블록을 블록으로 판별한다.
- 구문 강조 요소의 재귀 행 분할을 적용하고, 토큰에 적용하던 최소 높이를 제거했다. 실제 빈 행과 들여쓰기를 유지한다.
- Monaco 코드 배경을 반투명하게 변경해 선택 색을 가리지 않도록 했다. 설치된 데스크탑의 실제 선택 화면은 아직 미확인이다.
- HTML 가져오기에서 제목과 원본 코드 메타데이터를 복원한다. HWPX 출력에도 전체 제목과 원본 코드 텍스트를 사용한다.
- `frontend/scripts/verify-code-blocks.mjs`: 실제 CodeBlock 렌더러와 Markdown 파서로 전체 제목, 0/1/4행, 실제 빈 줄, 강조 토큰, HTML 왕복 보존 검증 통과.
- 타입 검사 및 HWPX 구조 검증 통과. 데스크탑 빌드 검증 수행.
- 남은 시각 검증: 웹/설치 데스크탑의 선택 방향·테마·포커스 전환, PDF/EPUB/HWPX 리더의 실제 조판. 이 항목은 빌드나 문자열 검사만으로 통과 처리하지 않는다.

## 2. 문제와 소스 확인 결과

| 우선순위 | 문제 | 확인 결과 | 조치 방향 |
| --- | --- | --- | --- |
| P0 | 코드블록에서 선택한 텍스트가 표시되지 않음. 복사·잘라내기·붙여넣기는 가능 | 문의와 첨부 화면으로 증상 확인. MainEditorApp의 전체 행 장식 `monaco-codeblock-line`과 globals.css의 불투명 배경 확인. 선택 영역을 가리는지는 실제 Monaco DOM 재현 필요 | 선택 상태를 유지하면서 배경 장식과 선택 영역의 표시 순서를 바로잡음 |
| P1 | `추천 디렉토리 구조`가 `추천`으로만 표시됨 | MarkdownViewer의 `/language-(\S+)/`가 첫 단어만 추출하고 CodeBlock 헤더가 이 값을 사용함 | fence 전체 정보와 언어를 분리하여 전체 제목 보존 |
| P1 | 원본에 없는 빈 줄처럼 큰 간격이 생김 | 행 래핑과 구문 강조 자식 모두에 `min-height: 1.35em` 적용. CodeBlock은 정리된 code 대신 원래 children을 행으로 분할하므로 파서의 마지막 개행도 추가 행이 될 수 있음 | 물리 행당 하나의 행 요소만 높이를 가지도록 하고 마지막 파서 개행 처리 통일 |
| P1 | 언어 없는 한 줄 코드블록의 블록/인라인 판별 불안정 | 언어 클래스와 본문의 개행 존재로 인라인 여부를 추정함 | AST의 pre/code 구조로 구분 |
| P2 | 미리보기와 내보내기·재가져오기에서 제목/개행이 달라질 위험 | exportHandlers와 MainEditorApp에서 행간 CSS를 별도로 생성하고 importHtmlMarkdown은 헤더를 제거함 | 공통 메타데이터와 CSS 규칙을 사용하고 왕복 보존 검증 |

첨부 2번의 닫는 fence 뒤 `/` 같은 문법은 별도 확인한다. 원본이 잘못 작성된 경우에도 내용을 자동 삭제하거나 수정하지 않고, 편집기 영역 판별과 미리보기 파서가 동일하게 해석하도록 한다.

## 3. 구현 설계

### 3.1 P0 — 선택 표시 복구

대상: `frontend/src/components/MainEditorApp.tsx`, `frontend/src/app/globals.css`, 필요 시 `frontend/src/lib/editorThemes.ts`.

1. 코드블록 안/밖의 드래그 선택을 같은 문서로 재현한다. 실제 `.selected-text`, 행 장식, 현재 행 강조의 DOM 위치·배경·겹침을 확인한다.
2. 배경 장식이 선택을 가리면 Monaco가 제공하는 장식 계층/옵션을 우선 사용해 선택이 드러나도록 변경한다. 불투명한 배경이 원인인 경우 배경 색상과 투명도를 조정한다.
3. 선택 영역에만 필요한 범위로 CSS를 제한한다. 전체 Monaco 계층의 z-index를 일괄 변경하지 않는다.
4. 코드블록의 회색 영역 표시와 커서·현재 행 강조를 유지한다. 네이티브 선택 상태나 복사·잘라내기 동작을 새로 구현하지 않는다.

완료 기준: 정방향/역방향 드래그, Shift+방향키, Ctrl+A, 다중 행, 코드블록 경계를 넘는 선택이 밝은/어두운 테마와 포커스 전환 후에도 식별된다. 복사·잘라내기·붙여넣기와 실행 취소는 기존대로 동작한다.

### 3.2 P1 — 제목과 언어 분리

대상: `frontend/src/components/MarkdownViewer.tsx`, 신규 공통 코드블록 메타데이터 유틸리티, `frontend/src/lib/editorUtils.ts`의 fence 판별.

1. Markdown AST에서 fence의 전체 info 문자열과 원본 행 범위를 읽어 렌더러에 전달한다. `language-*` 클래스에서 제목을 복원하지 않는다.
2. 내부 모델에 `rawInfo`, `language`, `title`, `rawCode`, `sourceStartLine`을 구분한다.
3. 기존 사용자 문법을 다음과 같이 보존한다.

| fence 정보 예시 | 헤더 | 구문 강조 |
| --- | --- | --- |
| `추천 디렉토리 구조` | 추천 디렉토리 구조 | 일반 텍스트 |
| `소스코드` | 소스코드 | 일반 텍스트 |
| `kotlin` | kotlin | Kotlin |
| `kotlin title="추천 디렉토리 구조"` | 추천 디렉토리 구조 | Kotlin |
| 정보 없음 | 코드 | 일반 텍스트 |

4. 알 수 없는 언어·제목은 본문을 그대로 렌더링한다. Mermaid 등 기존 특수 블록의 분기와 언어별 구문 강조를 유지한다.
5. 긴 제목은 복사 버튼과 겹치지 않도록 헤더 높이를 유연하게 처리한다. `uppercase`로 사용자 제목의 원래 대소문자를 바꾸지 않는다.
6. 인라인 코드와 fenced/indented 코드블록은 AST 구조로 판별한다. 빈 블록과 언어 없는 한 줄 블록도 블록으로 유지한다.
7. 인용문·목록 내부, 물결표 fence, 긴 fence, 코드 안의 짧은 fence 예시를 편집기와 미리보기에서 비교한다. 영역 마스크가 파서와 다르면 같은 구문 규칙으로 맞춘다.

완료 기준: 공백 포함 한글 제목이 모두 표시되고 제목이 본문에 섞이지 않는다. 기존 MD를 다시 저장할 때 본문과 fence 문자열을 임의 변경하지 않는다.

### 3.3 P1 — 행 간격과 원본 공백 보존

대상: MarkdownViewer의 `splitChildrenIntoLines`/CodeBlock, globals.css, MainEditorApp의 동적 서식 CSS, exportHandlers의 코드블록 CSS.

1. 최소 높이는 각 `.onrivi-line` 행 컨테이너에만 적용한다. 구문 강조용 내부 span에는 높이·패딩·블록 표시를 주지 않는다.
2. 중첩된 구문 강조 요소까지 재귀적으로 분할하며 텍스트·토큰 순서와 스타일을 보존한다. LF/CRLF는 렌더링 경계에서 처리한다.
3. 파서가 덧붙이는 마지막 개행과 원본의 의도적인 빈 줄을 구분한다. `trim()`으로 들여쓰기나 선후행 빈 줄을 통째로 삭제하지 않는다.
4. 행 수와 `data-line`을 원본 코드의 물리 행에 맞춘다. 빈 행도 하나의 행으로 계산하고 하이라이트가 인접 행으로 밀리지 않게 한다.
5. `pre`, `code`, 행 요소의 중복 행간·높이 규칙을 정리한다. 사용자가 지정한 코드블록 행간은 한 곳의 규칙으로 반영한다.
6. 복사 버튼은 헤더·복사 버튼 문구·빈 행용 보조문자를 제외한 원본 코드 텍스트를 복사한다.

완료 기준: `fun FolderScreen()`, `{`, 들여쓴 `println("hello")`, `}`의 4행 예시는 4행으로 표시한다. 원본에 빈 줄을 넣은 경우에만 해당 빈 줄이 표시된다. 탭·들여쓰기·기호와 복사 결과가 보존된다.

### 3.4 P2 — 가져오기와 내보내기 일관성

1. HTML은 코드블록 제목·언어 메타데이터와 코드 본문을 별도 보존한다. 가져오기 시 시각적 헤더를 제거하기 전에 메타데이터를 읽어 fence에 복원한다.
2. EPUB도 같은 정보를 보존하며 다른 출처의 pre/code에는 표준 언어 클래스와 실제 본문을 사용한다.
3. PDF와 HWPX는 제목과 첫 본문 행이 불필요하게 분리되지 않도록 하고 본문 빈 줄·들여쓰기를 유지한다. 페이지보다 긴 코드블록은 본문 분할을 허용한다.
4. 복사 버튼과 커서 위치 강조는 출판 결과에 포함하지 않는다.
5. 미리보기·동적 서식·내보내기의 행간 정책을 공통화하여 한 화면만 수정되는 상황을 방지한다.

## 4. 검증 계획

| 구분 | 필수 사례 | 합격 기준 |
| --- | --- | --- |
| 편집기 | 웹/데스크탑, 밝은/어두운 테마, 선택 방향·키보드 선택·다중 행·포커스 전환 | 선택 식별 가능, 편집 명령 정상 |
| 제목 | 한글 공백 제목, 영어 제목, 언어만, 언어+제목, 정보 없음, 긴 제목 | 전체 제목 보존, 본문과 분리 |
| 코드 내용 | 0/1/4행, 실제 빈 줄, 마지막 빈 줄, 탭, CRLF, 중첩 토큰, HTML 기호, 디렉토리 트리 | 내용·물리 행 수·들여쓰기 보존 |
| 문법 | 인라인, 들여쓴 코드, 인용문/목록 안의 fence, 긴 fence, 미닫힘 fence, Mermaid | 파서 해석과 편집기 장식 일치 |
| 동기화 | 코드 모든 행으로 커서 이동, 편집 후 행 추가·삭제 | 올바른 원본 행 강조와 스크롤 |
| 내보내기 | HTML/PDF/EPUB/HWPX, HTML/EPUB 재가져오기 | 제목·언어·본문·빈 줄 보존, 불필요한 UI 제외 |

자동 검증은 제목 메타데이터, 행 분할, fence 범위, 왕복 텍스트 보존을 대상으로 한다. 선택 표시와 실제 간격은 웹 및 데스크탑에서 화면으로 검증한다. 타입 검사와 데스크탑 빌드 후 결과를 기록한다. 빌드 성공만으로 시각적 결함 해결을 선언하지 않는다.

## 5. 실행 순서와 산출물

1. 첨부 사례를 재현하는 작은 MD 문서와 현재 화면 기록 작성.
2. 선택 표시 복구 후 웹/데스크탑 확인.
3. 제목 메타데이터와 블록 판별 수정.
4. 행 분할·CSS·복사·커서 동기화 수정.
5. 내보내기/재가져오기 연결 및 회귀 검증.
6. 검증 결과표, 수정 전후 화면, 미확인 항목 작성. 배포와 설치 앱 적용 여부를 별도 명시.

산출물: 수정 코드, 재현용 MD, 필요한 회귀 검증, 웹/데스크탑 검증 결과. 작업량은 실제 Monaco 선택 문제의 원인과 코드블록 파서 공통화 범위를 확인한 뒤 확정한다.
