## AI-001 — AI 안정성 개선 및 기본 문서 변환 분리

- 등록일: 2026-10-03
- 상태: 보류 — 사용자 요청으로 차후 별도 작업
- 착수 조건: 사용자가 재개를 요청하면 요구사항과 설계를 확정한다.
- 목적: 외부 AI 장애 시에도 기본 문서 작업을 계속하고, 실패한 AI 작업을 다시 진행할 수 있도록 한다.

### 발생 배경

Gemini `gemini-3.7-flash` 문서 변환 요청에서 입력 5,584자, 대기 7,626ms 후 HTTP 503이 발생했다. 앱의 2분 제한에 도달한 사례가 아니라 외부 서버가 반환한 오류다. 일반 유료 API 전환만으로 장애가 없어지는 것은 보장할 수 없다.

### 현재 반영된 조치

- AI 변환 실패 시 추출된 HTML을 `.md`로 저장하던 처리 제거.
- 문서 크기 초과·API 키 누락 시 변환을 중단하고 오류 표시.
- 일시적 서버 오류(500/503/504)는 같은 모델로 최대 3회 시도하고 대기 간격을 늘림.
- 전체 요청과 재시도를 포함해 최대 2분으로 제한.
- 문서 변환 시 재시도 안내 표시.
- 이미지 위치는 유지하면서 긴 내장 이미지 데이터를 AI 입력에서 제외.
- 실패 진단에 모델, 입력 길이, 경과 시간, 오류 종류 기록.
- 타입 검사 및 자동 테스트 7개 통과. 실제 외부 API 안정성 검증은 별도 필요.

### 추후 작업 목록

- [ ] DOCX·HTML의 제목, 표, 목록, 이미지 등을 AI 없이 마크다운으로 변환하는 정식 기능 설계 및 구현.
- [ ] 기본 변환과 AI 서식 복원·정리 기능을 사용자가 구분해 선택할 수 있도록 구성.
- [ ] 실패한 AI 작업의 원문과 요청 조건을 보관하고 다시 시도하는 기능.
- [ ] 대기·재시도·완료·실패·취소 상태와 안내 화면 정리.
- [ ] 동시 요청 제한과 작업 대기열 도입 검토.
- [ ] 반복 장애 모델에 대한 호출 일시 중단 및 회복 확인 도입 검토.
- [ ] Gemini·OpenAI 등 제공자 선택 및 사용자가 다른 AI로 재시도하는 기능 검토.
- [ ] 실제 대표 문서로 성공률, 응답 시간, 비용을 측정하고 운영 기준 결정.

### 유지해야 할 요구사항

- AI 실패를 성공으로 표시하거나 HTML을 몰래 대체 저장하지 않는다.
- AI 실패·취소로 원문이나 기존 문서를 덮어쓰지 않는다.
- 불완전하거나 잘린 결과는 완성된 결과로 적용하지 않는다.
- 다른 제공자로 문서를 전송할 때는 사용자가 선택한 설정과 데이터 전송 범위를 따른다.
- AI 장애 중에도 기존 파일의 열기·편집·저장 작업을 사용할 수 있도록 한다.

### 재개 시 결정할 사항

기본 변환 대상과 품질 기준, 작업 보관 위치·기간, 제공자별 API 키 관리, 재시도·취소 정책, 운영 비용과 허용 지연 시간을 확정한다. 현재는 해당 추가 구현을 진행하지 않는다.

## UI-001 — 빠른 작업 템플릿 관리

- 등록일: 2026-10-11
- 상태: 보류 — 사용자 요청으로 다음에 진행
- 착수 조건: 사용자가 재개를 요청하면 구현한다.
- 현재 완료: 상단 버튼 영역에 ‘빠른 작업’ 이름 추가. 새 문서작성·파일 열기·사진 넣기·문서 저장 버튼은 기존 기능에 연결되어 있다.

### 추후 작업 목록

- [ ] 환경설정에 빠른 작업 관리 화면 추가.
- [ ] 처음 시작·전자책 제작·블로그 작성 템플릿 제공.
- [ ] 버튼 이름·순서·표시 여부 및 시작 안내 문구 편집.
- [ ] 버튼을 기존 명령에 연결하고, 웹·데스크탑의 지원 여부와 사용 가능 상태 반영.
- [ ] 선택한 템플릿과 사용자 설정을 저장하고 다음 실행 시 복원.
- [ ] 기본 구성 복원 기능 제공.

### 재개 시 결정할 사항

설정 저장 위치와 기기 간 공유 여부, 기본 템플릿별 버튼 구성을 확정한다. 템플릿 관리 기능은 아직 구현하지 않았다.
