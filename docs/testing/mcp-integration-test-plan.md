# 온리비 어서 MCP 통합 테스트 계획서

**대상:** 로컬 데스크톱 MCP 플러그인 `onrivi-author` 0.1.8  
**작성일:** 2026-10-29  
**상태:** 실행 전 계획서

## 1. 목적과 범위

Codex와 온리비 어서 데스크톱 앱을 함께 실행했을 때, MCP가 현재 선택한 **로컬 작업장·리소스 폴더**와 활성 유료 라이선스를 기준으로 동작하는지 검증한다. 파일 읽기·검색·생성·수정, 서식 조회·생성·수정, 권한 차단, 앱과의 동기화를 끝까지 확인한다.

대상 도구는 다음 10개다.

| 영역 | 도구 |
| --- | --- |
| 연결 | `get_current_folders` |
| 작업장 탐색 | `list_workspace_files`, `search_workspace` |
| 문서 | `read_markdown`, `create_markdown`, `replace_markdown`, `edit_markdown_section` |
| 서식 | `list_style_profiles`, `create_style_profile`, `update_style_profile` |

웹드라이브 기반 원격 MCP, 모바일 리더, RAG 인덱스는 아직 구현 대상이므로 이 계획의 합격 판정에 포함하지 않는다. 해당 기능을 만들 때 저장소·인증·동기화 테스트를 별도로 추가한다.

## 2. 테스트 환경과 준비

1. Windows 테스트 PC에 Node.js 20 이상, 온리비 어서 데스크톱 앱, Codex, 로컬 플러그인 0.1.8을 설치한다. `tools/list`에 위 10개 도구가 보이는지 확인한다.
2. **테스트 전용** 로컬 작업장과 리소스 폴더를 만든다. 실제 사용자 문서나 운영용 `userCssProfiles.json`을 수정하지 않는다.
3. 작업장에 `intro.md`, 중첩 폴더의 `notes.md`, 같은 제목이 두 번 있는 문서, 코드 펜스 안에 `# 제목`이 있는 문서, 한글 파일명 문서, 512 KiB 초과 검색용 문서, 2 MiB 초과 읽기용 문서를 준비한다.
4. 리소스 폴더에 정상 형식의 `profiles/userCssProfiles.json`과 복제 가능한 기본 서식을 준비한다. 시작 전 두 폴더의 파일 목록·SHA-256을 기록하고 백업한다.
5. 권한 시험에는 활성 유료 데스크톱 테스트 계정과, 무료·만료·세션 회수 상태를 만들 수 있는 별도 테스트 계정을 사용한다. 운영 라이선스를 임의로 변경하지 않는다.
6. Codex와 온리비 어서 앱을 재시작해 설치본·현재 폴더 정보가 갱신된 상태에서 시작한다. 테스트 중에는 도구 호출 시각, 결과, 파일 해시만 기록하고 결제번호·기기 ID·문서 전문은 공유 로그에서 가린다.

## 3. 실행 순서

### 단계 A — 자동 회귀 검사

저장소 루트에서 아래 명령을 실행한다. Windows 샌드박스가 임시 파일의 이름 변경을 거부하면 일반 권한의 테스트 셸에서 재실행하고 환경 오류로 따로 기록한다.

```powershell
node scripts/check-plugin-current-folders.mjs
node scripts/check-plugin-authorization.mjs
node scripts/check-plugin-document-scope.mjs
node scripts/check-plugin-style-profiles.mjs
node scripts/check-plugin-workspace.mjs
```

각 스크립트가 종료 코드 0으로 끝나고 성공 메시지를 출력해야 한다. 이는 단위·경계 검사이며, 아래 실제 앱 연결 시험을 대체하지 않는다.

### 단계 B — 실제 Codex ↔ 데스크톱 통합 시나리오

각 행은 독립된 테스트 케이스다. 쓰기 케이스 뒤에는 디스크 파일과 온리비 어서 화면을 모두 확인한다.

| ID | 시나리오와 절차 | 기대 결과 |
| --- | --- | --- |
| MCP-01 | 앱에서 테스트 폴더 2개를 선택하고 `get_current_folders` 호출 | 두 경로, `localReady=true`, 현재 `contextSha256` 반환 |
| MCP-02 | `list_workspace_files(limit=1)` 후 `nextCursor`로 다음 페이지 호출 | 중복 없이 다음 마크다운 파일 반환; 작업장 밖 파일 제외 |
| MCP-03 | `search_workspace(query=...)`로 파일명·본문·한글 검색 | 일치 파일, 행 번호, 짧은 발췌만 반환; 전문 미반환 |
| MCP-04 | `read_markdown`으로 기존 문서 읽기 | 원문과 정확한 SHA-256 반환; 앱의 문서 내용과 일치 |
| MCP-05 | `get_current_folders`의 해시로 `create_markdown` 호출 | 작업장 안에 새 파일 1개 생성; 앱에서 열어 정상 표시 |
| MCP-06 | MCP-05와 같은 경로로 다시 생성 | 실패하며 기존 파일·해시 불변 |
| MCP-07 | `read_markdown`의 해시로 `replace_markdown` 호출 | 전체 내용 교체, 새 해시 반환; 앱 재열기/새로고침 후 새 내용 표시 |
| MCP-08 | 고유 제목·기존 문구로 `edit_markdown_section` 호출 | 해당 문구만 변경; 다른 제목·코드 블록·줄바꿈 유지 |
| MCP-09 | `list_style_profiles` 호출 | 시스템/사용자 서식 구분, 서식 파일 해시와 폴더 해시 반환 |
| MCP-10 | 기존 서식을 기반으로 `create_style_profile` 호출 | 새 사용자 서식 1개 추가; 원본 서식 불변; 앱 서식관리에서 확인 |
| MCP-11 | 새 서식 ID와 최신 해시로 `update_style_profile` 호출 | 지정 속성만 바뀌고 다른 속성·서식은 유지; 앱에 반영 |
| MCP-12 | 앱에서 작업장 또는 리소스 폴더를 변경한 뒤 이전 `contextSha256`으로 쓰기 | 저장 거부; 이전/새 폴더 모두 원치 않는 변경 없음 |

### 단계 C — 권한·경계·충돌 시험

| ID | 조건과 절차 | 기대 결과 |
| --- | --- | --- |
| SEC-01 | 온리비 어서 앱 종료 또는 90초 넘게 폴더 정보 갱신 중단 | 모든 도구 호출 거부; 이후 쓰기 없음 |
| SEC-02 | 무료·만료·제한 세션에서 읽기와 쓰기 각각 호출 | 라이선스 오류로 거부; 파일 변경 없음 |
| SEC-03 | 유효 세션을 서버에서 회수하고 60초 캐시 만료 뒤 재호출 | 읽기와 쓰기 거부. 현재 설계의 최대 60초 캐시 지연은 결과에 명시 |
| SEC-04 | 라이선스 서버 연결 실패 상태에서 캐시 만료 뒤 호출 | 권한 확인 실패로 거부; 오프라인 우회 없음 |
| SEC-05 | 작업장 밖 절대경로, `..` 상대경로, 심볼릭 링크 경로로 읽기/생성/수정 시도 | 모두 거부; 외부 파일 불변 |
| SEC-06 | `read_markdown` 후 다른 프로세스에서 파일을 수정하고 이전 해시로 쓰기 | 변경 충돌로 거부; 다른 프로세스의 수정 내용 유지 |
| SEC-07 | `list_style_profiles` 후 JSON을 수정하고 이전 해시로 서식 쓰기 | 변경 충돌로 거부; 수동 변경 내용 유지 |
| SEC-08 | 시스템 서식 ID 수정, 중복 서식 이름, CSS에 `url(...)`·세미콜론 입력 | 모두 거부; 서식 파일 불변 |
| SEC-09 | 같은 제목/같은 기존 문구가 여러 개인 문서에서 부분 수정 시도 | 모호한 수정 거부; 문서 불변 |

### 단계 D — 한계·사용성 시험

| ID | 조건과 절차 | 기대 결과 |
| --- | --- | --- |
| LIM-01 | 2 MiB 초과 문서 읽기·생성 시도 | 크기 제한 오류; 파일 생성·교체 없음 |
| LIM-02 | 512 KiB 초과 검색 대상, 다수 파일, `limit` 최대·초과 입력 | 큰 파일은 건너뛰고 제한 정보를 반환; 최대값 초과 입력 거부 |
| LIM-03 | 숨김 폴더·심볼릭 링크·마크다운이 아닌 파일을 탐색 | 목록·검색 결과에서 제외 |
| LIM-04 | 새 파일과 수정 파일을 온리비 어서에서 열고 문서보기 모드로 전환 | 렌더링과 상대경로 이미지가 정상인지 확인; 실패하면 앱 동기화 결함으로 기록 |
| LIM-05 | Codex 재시작 후 플러그인 로고, 0.1.8 버전, 도구 목록 확인 | 설치본을 정확히 표시하고 10개 도구 사용 가능 |

## 4. 기록·판정 기준

각 케이스에 **실행 시각, PC/앱/플러그인 버전, 입력 요약, 기대 결과, 실제 결과, 통과/실패/차단, 파일 전후 해시, 오류 메시지, 재현 절차**를 기록한다. 개인정보와 라이선스 원문은 저장하지 않는다.

출시 전 합격 기준:

- 단계 A의 스크립트 전부 통과
- 단계 B의 MCP-01~12 전부 통과
- 단계 C에서 권한 우회·작업장 밖 접근·의도하지 않은 덮어쓰기 **0건**
- 단계 D의 한계가 문서화된 대로 작동하고, 앱 화면 반영에 재현 가능한 실패가 없을 것

실패한 케이스는 수정 후 동일 케이스와 관련 회귀 케이스를 재실행한다. 특히 `SEC-03`은 즉시 차단을 기대하는 시험이 아니라 **현재 60초 캐시 정책의 실제 차단 시점**을 확인하는 시험이다. 더 짧은 회수 시간이 필요하면 정책을 변경한 뒤 기준을 다시 정한다.

## 5. 산출물

테스트 결과표, 오류별 재현 기록, 전후 해시 목록, 앱 화면 캡처, 최종 합격/보류 결정을 이 문서와 함께 보관한다. 테스트용 파일은 운영 자료와 분리해 유지하거나 검증 후 정리한다.
