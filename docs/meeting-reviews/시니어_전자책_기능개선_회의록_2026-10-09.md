# 시니어 전자책 제작 지원을 위한 Onrivi Author 기능 개선 회의록

> **회의자**: 박현희 강사님  
> **장소**: 수원시 장안구청 4층 정보화실  
> **과목**: J 매달 연금 받는 전자책 제작법 1  
> **회의시간**: 오후 4시 30분 전후  
> **회의목적**: 시니어 사용자의 전자책 제작을 지원하기 위한 Onrivi Author 기능 개선 및 사용환경 협의

---

## 1. 회의 목적

시니어 사용자가 복잡한 프로그램 조작이나 파일 관리 방법을 별도로 학습하지 않아도 전자책을 쉽고 편리하게 제작할 수 있도록 **Onrivi Author의 사용 편의성과 접근성을 개선**한다.

전자책에 필요한 글은 AI를 적극 활용하여 작성하고, 사용자는 Onrivi Author에서 작성된 콘텐츠를 가져와 이미지와 이모지를 추가하고 문서를 편집한 후 PDF·전자책 등의 최종 결과물로 내보낼 수 있도록 한다.

특히 사용자가 직접 수행해야 하는 초기 환경설정과 파일 관리 작업을 최소화하여 다음과 같은 단순한 제작 흐름을 제공하는 것을 기본 방향으로 한다.

**AI 콘텐츠 작성 → Onrivi Author 편집 → 이미지·이모지 추가 → 미리보기 → PDF·전자책 내보내기 → 완성 결과물 확인**

---

## 2. 주요 회의 내용

### 2.1 AI 기반 전자책 작성 및 콘텐츠 편집 지원

전자책에 필요한 글은 AI를 활용하여 작성하고, Onrivi Author에서는 사용자가 해당 콘텐츠를 편집하면서 이미지와 이모지 등을 간편하게 추가할 수 있도록 한다.

### 주요 요구사항

- 전자책의 글은 AI를 활용하여 작성한다.
- 사용자는 AI에서 작성한 내용을 Onrivi Author로 가져와 편집할 수 있도록 한다.
- 이모지를 별도의 검색이나 복잡한 입력 없이 **한 번의 클릭으로 목록을 열어 선택**할 수 있도록 한다.
- Gemini 등 외부 AI 서비스 또는 이미지 생성 프로그램에서 만든 이미지를 **마우스 드래그 앤 드롭 방식으로 Onrivi Author에 삽입**할 수 있도록 한다.
- 외부 프로그램이나 웹에서 복사한 이미지를 Onrivi Author 편집영역에 **붙여넣기(Ctrl+V)** 할 수 있도록 한다.
- 이미지가 삽입될 경우 필요한 리소스 파일 관리가 자동으로 이루어지도록 한다.
- 시니어 사용자가 파일 경로나 이미지 저장 위치 등을 직접 관리해야 하는 작업을 최대한 줄인다.

---

### 2.2 최초 사용자의 접근성 개선

Onrivi Author를 처음 사용하는 사용자가 별도의 환경설정 과정을 학습하지 않아도 곧바로 글쓰기를 시작할 수 있도록 초기 설정 절차를 최소화한다.

### 주요 요구사항

- 최초 실행 시 작업장(Workspace) 설정을 자동화한다.
- 리소스 폴더를 자동으로 생성하고 연결한다.
- 기본 작업장을 제공하여 별도의 경로 설정 없이 새 문서를 작성할 수 있도록 한다.
- Google Drive 사용 시 필요한 작업 폴더와 리소스 폴더 및 관련 파일을 자동으로 구성하도록 한다.
- 사용자가 파일 시스템 구조를 이해하지 않아도 프로그램을 사용할 수 있도록 한다.

궁극적으로 최초 사용자가 복잡한 설정 화면을 거치지 않고 다음과 같은 흐름으로 사용할 수 있도록 한다.

**Onrivi Author 실행 → 새 글 작성 → 바로 전자책 제작 시작**

---

### 2.3 개인 클라우드 기반 문서 관리

사용자가 특정 PC에 종속되지 않고 장소와 기기에 관계없이 자신의 전자책 문서를 열고 수정할 수 있도록 **개인 클라우드 저장공간을 활용하는 방안**을 적용한다.

공용 클라우드 저장공간을 별도로 구축할 경우 서버 및 스토리지 운영비용과 관리 부담이 발생하므로 현재 단계에서는 사용자가 보유한 **개인 Google Drive를 활용하는 방식**을 우선 적용한다.

개인 Google 계정을 사용하는 경우 Google Drive 저장공간을 활용할 수 있으므로 별도의 공용 저장공간을 구축하는 것보다 현실적인 구현방안으로 판단한다.

또한 Onrivi Author가 개인 문서와 콘텐츠를 다루는 프로그램이라는 특성을 고려하여 공용 저장공간보다 **개인 소유의 클라우드 저장공간을 사용하는 방식이 문서 관리 및 보안 측면에서도 적합**하도록 설계한다.

### 주요 지원 방향

- 개인 Google Drive에 Onrivi Author 작업파일 저장
- 다른 PC에서도 동일 Google 계정을 이용하여 문서 접근
- 기존 문서 열기 및 수정
- 이미지·동영상 등 문서 리소스 관리
- 개인별 저장공간을 활용한 문서 관리
- 로컬 PC와 Google Drive 작업환경 선택

## 3. 협의 결과 및 조치계획

### 3.1 이모지 선택 기능 구현

Onrivi Author 오른쪽 툴바에 **이모지 선택 기능**을 추가한다.

스마일 아이콘을 클릭하면 이모지 목록 패널이 표시되고, 사용자가 원하는 이모지를 선택하면 현재 편집 위치에 즉시 삽입되도록 구현한다.

### 구현 흐름

**오른쪽 툴바 → 스마일 아이콘 → 이모지 패널 → 이모지 선택 → 편집영역 삽입**

사용자가 이모지 입력방법이나 별도의 단축키를 학습하지 않아도 사용할 수 있도록 최대한 단순한 인터페이스를 적용한다.

---

### 3.2 이미지 드래그 앤 드롭 및 붙여넣기 지원

Gemini, 이미지 생성 프로그램, 웹브라우저 등 외부 프로그램에서 이미지를 Onrivi Author로 직접 가져올 수 있도록 한다.

### 드래그 앤 드롭 방식

1. 외부 프로그램에서 이미지를 선택한다.
2. 이미지를 Onrivi Author 편집영역으로 드래그한다.
3. 원하는 위치에서 마우스를 놓는다.
4. 이미지를 문서에 자동으로 삽입한다.
5. 필요한 경우 지정된 리소스 폴더에 이미지 파일을 자동 저장한다.

### 복사 및 붙여넣기 방식

외부 프로그램이나 웹에서 이미지를 복사한 후 Onrivi Author 편집영역에서 **Ctrl+V**를 실행하면 이미지가 자동으로 삽입되도록 한다.

삽입된 이미지의 저장 및 리소스 관리도 가능한 범위에서 자동으로 처리하여 사용자가 이미지 파일을 별도로 저장하고 경로를 지정해야 하는 과정을 최소화한다.

---

### 3.3 초기 작업환경 자동 설정

현재 Onrivi Author의 기본 설정방식은 유지하되, 일반 사용자가 직접 설정해야 하는 항목을 최소화한다.

특히 시니어 사용자의 최초 접근성을 높이기 위해 작업장과 리소스 폴더 설정을 자동화한다.

| 구분 | 기존 방식 | 개선 방향 |
| --- | --- | --- |
| 작업장 설정 | 사용자 직접 설정 | 기본 작업장 자동 설정 |
| 리소스 폴더 | 사용자 직접 지정 | 자동 생성 및 연결 |
| 새 문서 작성 | 환경설정 후 사용 | 최초 실행 후 즉시 작성 |
| Google Drive | 사용자 설정 필요 | 연결 시 작업환경 자동 구성 |
| 이미지 관리 | 파일 및 경로 관리 필요 | 자동 저장 및 리소스 연결 |

이를 통해 사용자가 파일 시스템이나 폴더 구조를 이해하지 않아도 **프로그램 실행 후 바로 새 문서를 작성할 수 있는 환경**을 제공한다.

---

### 3.4 Google Drive 기반 클라우드 작업환경 구현

별도의 공용 클라우드 서버를 구축하는 대신 **사용자의 개인 Google Drive를 활용하는 방식**으로 구현한다.

공용 클라우드 방식은 별도의 저장공간 운영비용과 사용자 데이터 관리 부담이 발생하는 반면, 개인 Google Drive 방식은 사용자가 보유한 계정과 저장공간을 활용할 수 있다는 장점이 있다.

또한 Onrivi Author가 개인 문서의 관리와 보안을 중요하게 다루는 시스템이라는 점을 고려하여 공용 저장공간보다 개인 소유의 클라우드 저장공간을 활용하는 구조를 우선 적용한다.

Google Drive에 연결하면 Onrivi Author 사용에 필요한 기본 작업 폴더와 리소스 폴더 등을 자동으로 구성할 수 있도록 구현한다.

---

### 3.5 로컬 OS ↔ Google Drive 작업환경 전환

사용자가 상황에 따라 로컬 PC 또는 Google Drive를 선택하여 사용할 수 있도록 작업환경 전환 기능을 구현한다.

### 작업환경 전환

**로컬 OS 작업환경 ⇄ Google Drive 작업환경**

전환 시 문서뿐만 아니라 이미지와 동영상 등 관련 리소스도 해당 작업환경에 맞게 사용할 수 있도록 한다.

### 로컬 작업환경

**문서 → 로컬 작업장 → 로컬 리소스 폴더**

### Google Drive 작업환경

**문서 → Google Drive 작업장 → Google Drive 리소스 폴더**

Google Drive 환경에서도 로컬 환경과 최대한 동일한 기능을 제공하여 사용자가 저장 위치의 차이를 크게 의식하지 않고 작업할 수 있도록 한다.

---

### 3.6 이미지 및 동영상 리소스의 클라우드 지원

현재 로컬 OS에서 사용하는 이미지·동영상 리소스 관리 기능을 Google Drive에서도 동일하게 사용할 수 있도록 개선한다.

Google Drive 작업환경에서는 지정된 클라우드 리소스 폴더를 기준으로 다음 기능을 지원하도록 한다.

- 이미지 저장
- 이미지 불러오기
- 이미지 삽입
- 이미지 리소스 경로 관리
- 동영상 저장
- 동영상 불러오기
- 문서와 리소스 간 연결 유지

이를 통해 로컬 작업환경과 Google Drive 작업환경 간의 기능 차이를 최소화한다.

---

### 3.7 PDF·전자책 등 내보내기 기능 점검 및 결과물 검증

Onrivi Author에서 작성한 문서를 실제 전자책 제작 및 배포에 활용할 수 있도록 **내보내기(Export) 기능을 점검하고 최종 결과물을 검증**한다.

단순히 파일이 생성되는지만 확인하는 것이 아니라, Onrivi Author의 편집 및 미리보기 화면에서 구성한 문서가 최종 결과파일에서도 최대한 동일하게 유지되는지를 중점적으로 확인한다.

### 주요 점검 대상

- PDF 내보내기
- 전자책 형식 내보내기
- 기타 지원 문서 형식 내보내기
- 제목·본문·목록 등 문서 구조 유지 여부
- 글꼴 및 글자 크기 적용 여부
- 문단 스타일 적용 여부
- 페이지 크기 및 여백 유지 여부
- 페이지 구분 및 조판 상태
- 표의 크기 및 배치 상태
- 이미지 크기 및 위치 유지 여부
- 이모지 출력 상태
- 한글 표시 및 글자 깨짐 여부
- 이미지 누락 여부
- 문서 내부 링크 및 리소스 연결 상태
- 페이지 넘침 및 콘텐츠 잘림 여부

특히 시니어 사용자가 별도의 후처리 작업을 하지 않아도 되도록 **Onrivi Author에서 작성한 문서를 바로 활용할 수 있는 수준의 결과파일을 생성하는 것**을 목표로 한다.

---

### 3.8 내보내기 결과파일 테스트 및 제공

내보내기 기능 구현 및 점검 후 실제 전자책 예제 문서를 이용하여 PDF·전자책 등 지원 형식의 결과파일을 생성한다.

생성된 파일은 단순 생성 여부만 확인하지 않고 실제로 파일을 열어 문서의 내용과 조판 상태를 점검한다.

### 결과파일 검증 절차

**① Onrivi Author에서 테스트 문서 작성**  
↓  
**② 미리보기 화면에서 문서 구성 및 조판 확인**  
↓  
**③ PDF·전자책 등 지원 형식으로 내보내기**  
↓  
**④ 생성된 결과파일 직접 열기**  
↓  
**⑤ 문서 구조·이미지·이모지·표·조판 상태 확인**  
↓  
**⑥ 문제 발생 시 기능 수정**  
↓  
**⑦ 수정 후 결과파일 재생성**  
↓  
**⑧ 최종 결과파일 검증**  
↓  
**⑨ 검증 완료된 결과파일 제공**

최종 검증이 완료된 **PDF 및 전자책 등의 실제 결과파일을 테스트 자료와 함께 박현희 강사님께 제공**하여 직접 결과물을 확인할 수 있도록 한다.

## 4. 시니어 사용자 기준 목표 이용 흐름

이번 기능 개선을 통해 시니어 사용자가 실제 전자책을 제작할 때 다음과 같은 단순한 작업 흐름으로 이용할 수 있도록 한다.

### STEP 1. AI에서 글 작성

AI를 이용하여 전자책의 제목, 목차, 본문 등 필요한 콘텐츠를 작성한다.

↓

### STEP 2. Onrivi Author에서 문서 작성

AI에서 작성한 내용을 Onrivi Author로 가져와 전자책 문서를 구성한다.

↓

### STEP 3. 이모지 추가

오른쪽 툴바의 스마일 아이콘을 클릭하여 필요한 이모지를 선택하고 문서에 삽입한다.

↓

### STEP 4. 이미지 추가

Gemini 또는 이미지 생성 프로그램 등에서 제작한 이미지를 마우스로 끌어 Onrivi Author에 바로 삽입하거나 복사·붙여넣기 방식으로 추가한다.

↓

### STEP 5. 문서 편집 및 미리보기

제목, 본문, 이미지, 이모지 등을 확인하고 최종 문서 형태를 미리보기로 확인한다.

↓

## 10. 시나리오 가능 여부 및 검증 조건

### 10.1 검토 결론

현재 코드에는 이모지 삽입, 이미지 파일 드래그·붙여넣기, 로컬·Google Drive 리소스 구성, PDF·EPUB 내보내기 처리가 존재한다. 따라서 제시된 전자책 제작 흐름은 구현 방향으로 가능하다. 코드 존재만으로 실제 사용자 시나리오의 완료를 보장할 수는 없으며, 아래 검증을 통과한 범위만 사용 가능으로 확정한다.

| 시나리오 | 코드 검토 결과 | 실제 사용 시 확인할 조건 |
| --- | --- | --- |
| AI 글 가져오기 및 편집 | 문서 편집 경로 존재 | 제목·목록·표가 의도한 형태로 표시되는지 확인 |
| 이모지 선택 및 삽입 | 패널과 커서 삽입 처리 존재 | 연속 삽입, 저장·재열기, PDF·EPUB 출력 확인 |
| 이미지 파일 드래그·Ctrl+V | 파일·클립보드 처리 존재 | 파일을 제공하는 드래그·복사를 기준으로 검사 |
| Gemini·웹 이미지 직접 가져오기 | HTML·URL 처리 경로 존재 | 서비스별 인증·URL 접근에 따라 성공 여부가 다를 수 있음. 직접 가져오기 실패 시 내려받은 이미지 파일을 끌어 넣는 경로 제공 |
| 로컬 초기 작업환경 | 리소스 폴더 초기화 처리 존재 | 설정 없는 새 사용자로 시작해 작업장·리소스 생성과 재실행 복원 확인 |
| Google Drive 초기 연결 | 작업장·리소스 하위 폴더 및 초기 파일 구성 처리 존재 | 최초 로그인·권한 승인은 사용자 수행. 새 계정에서 자동 구성과 재연결 확인 |

| Google Drive 이미지·동영상 | 리소스 관리 경로 점검 필요 | 저장·재열기·접근 권한 검사. 동영상의 EPUB 내장 재생은 별도 지원 범위로 검증 |
| PDF 내보내기 | 내보내기 처리 존재 | 생성한 PDF를 직접 열어 글꼴·이미지·이모지·표·잘림 확인 |
| EPUB 내보내기 | XHTML·이미지 포함 처리 존재 | EPUB 읽기 프로그램에서 검사. 리더별 글꼴·화면 크기에 따른 재배치를 허용하며 PDF와 같은 페이지 배치를 완료 기준으로 삼지 않음 |

### 10.2 10월 9일 최소 종합 테스트

1. 설정 없는 사용자 환경에서 새 문서를 만든다.
2. AI 글을 붙여넣고 제목·목록·일반 표를 편집한다.
3. 이모지와 내려받은 이미지 파일을 삽입한다. 이미지 붙여넣기도 확인한다.
4. 저장 후 앱을 종료하고 다시 열어 문서·서식·이미지를 확인한다.
5. 새 Google Drive 계정으로 연결하여 자동 폴더 구성과 저장·재열기를 확인한다.
6. 로컬→Google Drive→로컬→Google Drive로 전환하고 각 환경의 서식·이미지를 확인한다.
7. 같은 예제 문서를 PDF와 EPUB로 내보내 각각 직접 연다.
8. 한글·이미지·이모지·표 누락과 내용 잘림이 없는 결과만 강사 확인용으로 제공한다.

외부 AI 서비스의 이미지 직접 드래그, 동영상의 전자책 재생, 모든 기기에서 같은 조판은 위 최소 테스트와 구분하여 별도 확인한다.
