> "방금 프로그램을 껐다 켰는데 아까 쓰던 글이 그대로 남아있네요. 그럼 이미 저장된 것 아닌가요?"  
> 많은 사용자가 가장 흔하게 오해하는 부분입니다. 화면에 글이 남아있는 것과 **실제 파일로 안전하게 기록된 것**은 완전히 다른 개념입니다. 소중한 원고를 영구히 지키기 위해 이 둘의 차이를 반드시 이해해야 합니다.

---

## 1. 개요: 저장의 두 가지 얼굴

온리비 어서(Onrivi Author)는 사용자의 편의와 데이터 안전을 위해 두 가지 상호보완적인 메커니즘을 함께 가동하고 있습니다.

```
┌──────────────────────────────────────┐       ┌──────────────────────────────────────┐
│       [1] 물리적 파일 저장            │       │       [2] 세션 탭 자동 복원          │
│          (Physical File Save)        │       │       (Session Tabs Restore)         │
├──────────────────────────────────────┤       ├──────────────────────────────────────┤
│ • 내 컴퓨터 SSD/HDD 디스크에 실제 쓰기  │       │ • 브라우저/앱 메모리(LocalStorage)에  │
│ • Google Drive 클라우드 서버에 쓰기  │       │   '열려있던 탭 목록'만 임시 기억     │
│ • 단축키 Ctrl+S 또는 자동 저장(AutoSave)│     │ • 앱 재시작 시 작업 화면을 복원하는 편의 │
│ • 50년 후에도 영구 보존되는 진짜 파일  │       │ • 브라우저 캐시 삭제 시 소멸 위험    │
└──────────────────────────────────────┘       └──────────────────────────────────────┘
```

1. **물리적 파일 저장 (Real Save)**: 실제로 내 컴퓨터의 하드디스크나 Google Drive 클라우드에 `.md` 파일 형태로 텍스트를 영구히 기록하는 행위입니다.
2. **세션 탭 자동 복원 (Session Restore)**: 컴퓨터가 갑자기 꺼지거나 실수로 창을 닫았을 때, 직전에 열려 있던 탭들의 상태를 기억해 두었다가 다시 띄워주는 **임시 안전망(Safety Net)**입니다.

## 2. 개념 1: 물리적 파일 저장 (Physical Save)

'물리적 저장'이란 내가 입력한 글자가 컴퓨터의 영구 저장 장치나 클라우드 드라이브에 안전하게 새겨지는 것을 의미합니다.

### ① 수동 저장 방법과 단축키
* **현재 파일 저장**: `Ctrl + S` (상단 메뉴: `파일(F) ➔ 저장`)
  * 이미 연결된 파일이 있다면 즉시 디스크/드라이브에 덮어써집니다.
  * 만약 아직 이름이 없는 새 문서(`새 파일.md`)라면, 파일 이름을 입력하는 저장 대화상자가 나타납니다.
* **다른 이름으로 저장**: `Ctrl + Shift + S` (상단 메뉴: `파일(F) ➔ 다른 이름으로 저장`)
  * 기존 원본은 그대로 두고, 새로운 이름의 복사본 파일로 분기하여 저장합니다.

### ② 환경별 실제 저장 동작 방식
온리비 어서는 구동되는 환경에 따라 최적화된 파일 쓰기 엔진을 사용합니다:
* **데스크톱 앱 (Electron)**: 운영체제 파일 시스템 API(`api.saveFile`)를 호출하여 내 PC 하드웨어 디스크에 직접 무소음으로 고속 기록합니다.
* **웹 브라우저 (로컬 폴더 연결)**: 브라우저 최신 기술인 **File System Access API**를 통해 내 컴퓨터의 실제 파일 핸들(`writable.write()`)에 직접 물리적으로 기록합니다.
* **Google Drive 연동 환경**: Google Drive REST API(`saveDriveFileContent`)를 통해 내 구글 드라이브의 원본 파일에 즉각 실시간 동기화합니다.

### ③ 저장 시 일어나는 온리비만의 특별한 작업
`Ctrl + S`를 눌러 저장이 완료되는 순간, 온리비 어서는 백그라운드에서 두 가지 스마트 작업을 함께 처리합니다:
1. **Frontmatter 서식 자동 주입**: 현재 문서에 적용되어 있는 CSS 서식 프로필 정보(`css_profile: "Onrivi 기본서식"`)가 마크다운 문서 최상단 메타데이터에 자동으로 갱신되어, 나중에 파일을 다시 열어도 내가 정한 서식이 그대로 유지됩니다.
2. **지식 베이스(Knowledge Hub) 자동 재색인**: 해당 문서가 지식 보관함에 등록된 문서라면, 수정된 본문 내용을 바탕으로 로컬 SQLite 벡터 데이터베이스가 비동기로 자동 갱신됩니다.

## 3. 개념 2: 세션 자동 복구 (Session Restore - `onrivi_tabs_session`)

많은 분이 "저장하지 않고 껐는데 다시 켜니 글이 그대로 있었다"며 안도하곤 합니다. 이것이 바로 온리비 어서의 **세션 자동 복구** 기능 덕분입니다.

### ① 어떻게 동작하나요?
* 온리비 어서는 사용자가 글을 쓰는 동안 브라우저/앱의 로컬 저장소(`LocalStorage`)에 `onrivi_tabs_session`이라는 이름으로 **현재 열려 있는 탭들의 메타데이터(문서 경로, 탭 제목, 활성 탭 ID)**를 지속해서 기록합니다.
* 컴퓨터가 강제 종료되거나 사용자가 실수로 브라우저 탭을 닫으려 할 때, **`beforeunload` 안전 플러시(`beforeunload_safety_flush`)** 엔진이 작동하여 최신 탭 상태를 순간적으로 스토리지에 밀봉 저장합니다.
* 앱을 다시 실행하면 `restoreSessionTabs` 루틴이 구동되어, 이전 세션에서 열려 있던 파일들을 순차적으로 다시 읽어와 원래 보던 화면 상태로 복원해 줍니다.

### ② 왜 세션 복구만 믿으면 위험한가요?
> [!주의]
> **세션 복구는 '영구 저장'이 아닙니다!**  
> 세션 복구 데이터는 컴퓨터나 브라우저의 임시 스토리지에 기대어 동작합니다. 만약 다음과 같은 상황이 발생하면 세션 데이터는 흔적도 없이 사라질 수 있습니다:
> 1. 브라우저의 '인터넷 사용 기록 / 쿠키 및 캐시 삭제'를 실행한 경우
> 2. 브라우저 시크릿 창(InPrivate 모드)에서 작업 후 창을 닫은 경우
> 3. PC 저장 공간 부족으로 브라우저가 임시 스토리지를 자동 정리한 경우
> 4. 원본 파일이 아직 디스크에 물리적으로 생성되지 않은 '새 파일.md' 상태였던 경우

따라서 세션 복구는 불의의 사고를 막아주는 **'임시 에어백'**으로 생각하시고, 중요한 원고는 반드시 실제 파일로 저장해 두어야 합니다.

## 4. 자동 저장 (Auto Save) 기능과 5초 디바운스 활용법

매번 `Ctrl + S`를 누르기 번거로운 분들을 위해 온리비 어서는 **자동 저장(Auto Save)** 기능을 기본 지원합니다.

![환경설정 모달](./assets/fig2_settings_modal.png)
*[그림] 환경설정 ➔ 일반 설정 ➔ 에디터 동작의 자동 저장(Auto Save) 설정*

### ① 자동 저장 주기 설정하기
1. 상단 메뉴바의 `도구(T) ➔ 환경 설정`을 클릭하거나, 우측 세로 툴바의 `톱니바퀴(⚙️)` 아이콘을 클릭합니다.
2. `일반 설정` 탭의 `에디터 동작` 구역에서 **자동 저장 (Auto Save)** 항목을 찾습니다.
3. 원하는 주기를 선택합니다:
   * **사용 안함 (0)**: 수동으로 `Ctrl + S`를 누를 때만 저장 (기존 작가 선호)
   * **5초 (권장)**: 타이핑을 멈추고 5초가 지나면 백그라운드에서 자동 디스크 쓰기 수행
   * **10초 / 30초 / 1분**: 작업 환경에 맞추어 주기 조절

### ② 디바운스(Debounce) 메커니즘
타이핑할 때마다 매 글자 단위로 디스크에 저장하면 컴퓨터가 버벅거리고 드라이브 수명이 줄어듭니다. 온리비 어서의 자동 저장은 **지능형 디바운스**를 적용하여, **"사용자가 타이핑을 멈춘 시점"**부터 시간을 측정하여 부드럽고 안전하게 저장을 완료합니다.

> [!중요]
> **새 문서('새 파일.md')는 자동 저장되지 않습니다!**  
> 아직 내 컴퓨터 어디에 어떤 이름으로 저장할지 정해지지 않은 가상 상태의 새 문서는 자동 저장 대상에서 제외됩니다. 새 글을 쓰기 시작했다면 **반드시 최초 1회는 `Ctrl + S`를 눌러 저장할 위치와 파일명을 지정**해 주세요. 이후부터는 설정한 주기에 맞춰 자동으로 실시간 저장됩니다.

## 5. 원고 유실을 100% 방지하는 4대 황금 수칙

글을 쓰는 작가에게 가장 큰 비극은 피땀 흘려 쓴 원고가 한순간에 날아가는 것입니다. 아래 4가지 습관만 들이면 원고 유실을 원천 차단할 수 있습니다.

1. **글을 쓰기 전에 먼저 파일 이름부터 정하세요**:  
   새 글을 시작하자마자 `Ctrl + S`를 눌러 `2026-10-10_초안.md`와 같이 이름을 부여해 두세요. 이때부터 자동 저장의 보호를 온전히 받을 수 있습니다.
2. **단락을 마칠 때마다 습관적으로 `Ctrl + S`를 누르세요**:  
   키보드 단축키 `Ctrl + S`는 모든 전문 작가들의 제2의 반사 신경입니다.
3. **상태바의 저장 상태 칩을 확인하세요**:  
   문서 탭 옆에 점(`•`) 표식이 있거나 저장 상태가 '수정됨(unsaved)'으로 되어 있다면 아직 디스크에 쓰이지 않은 상태입니다. 저장이 완료되면 '저장됨(saved)' 상태로 바뀝니다.
4. **Google Drive 클라우드 서재를 병행 활용하세요**:  
   로컬 컴퓨터 고장이나 분실이 걱정된다면, Google Drive 클라우드 서재를 연결해 두세요. 집에서도, 회사에서도, 노트북에서도 언제나 최신 원고를 안전하게 이어 쓸 수 있습니다.

## 6. 자주 묻는 질문 (FAQ)

### Q1. 저장 단축키 `Ctrl + S`를 눌렀는데 아무 반응이 없는 것 같아요.
**A.** 온리비 어서의 저장은 화면을 가리는 불필요한 팝업 없이 우측 하단 토스트 메시지와 상태바를 통해 '현재 파일에 안전하게 저장되었습니다'라는 메시지로 무소음 완료됩니다. 이미 파일명이 지정된 상태라면 조용하고 빠르게 디스크에 기록되니 안심하셔도 됩니다.

### Q2. '다른 이름으로 저장'을 하면 기존에 열려있던 탭은 어떻게 되나요?
**A.** 새 파일명으로 새 탭이 열리며 편집 포커스가 새 문서로 전환됩니다. 기존 파일은 직전 저장 시점의 상태 그대로 안전하게 보존됩니다.

### Q3. 갑자기 컴퓨터가 재부팅되었는데 열려있던 탭이 안 열려요.
**A.** 비정상 종료 시에도 좌측 사이드바의 `작업장 실폴더`를 열어보시면 이전에 저장해 두셨던 `.md` 파일이 폴더 안에 그대로 보관되어 있습니다. 탐색기에서 해당 파일을 클릭하시면 언제든 즉시 다시 열어보실 수 있습니다.
