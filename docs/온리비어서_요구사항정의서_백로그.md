# 온리비 어서 요구사항 정의서 및 초기 Backlog

- 작성일: 2026-10-30
- 목적: 현재 소스와 사용자 피드백을 기준으로 기능 요구사항과 검증 기준을 한곳에 정리한다.
- 범위: 데스크톱, 웹, 관리자 페이지, 로컬 MCP. 외부 드라이브 기반 MCP와 클라우드 RAG는 별도 설계·승인 전까지 범위에 넣지 않는다.
- 상태 표기: **구현 확인 필요**는 소스가 있어도 실제 사용 환경에서 검증이 끝나지 않았다는 뜻이다. **미구현**은 화면 또는 계획만 확인된 기능이다.

## 1. 제품 원칙

1. 문서는 사용자가 지정한 작업장에 저장하고, 리소스 폴더에는 서식·참조 자료·설정을 분리해 둔다.
2. 데스크톱은 로컬 파일을 우선 사용한다. 웹에서는 사용자가 연결한 Google Drive 작업장을 사용한다.
3. 기능을 실행하기 전에 환경, 작업장, 권한, 라이선스를 확인하고 실패 원인을 사용자에게 표시한다.
4. 파일 수정과 삭제는 원본 보존, 충돌 감지, 복구 가능성을 고려한다.
5. 같은 문서의 편집·미리보기·내보내기 결과는 가능한 한 일치해야 한다.

## 4. Backlog 운영 규칙

- Backlog는 아직 착수하지 않은 작업을 모은다. 상태는 Backlog → Ready → In progress → Testing → Done 순서로 사용한다.
- 각 항목에는 Module, Environment, Priority, 기대 동작, 완료 기준을 기록한다.
- 코드가 존재하는 기능은 검증 전까지 완료로 표시하지 않는다.
- 새 요구사항은 이 문서에 ID를 추가하고, 실제 작업은 독립적으로 검증할 수 있는 크기의 프로젝트 항목으로 등록한다.
- 이 문서는 초기 기준이다. 요금제별 제공 범위, 웹 MCP와 외부 드라이브 RAG는 별도 요구사항 확정 후 추가한다.
