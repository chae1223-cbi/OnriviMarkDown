# 그림책 템플릿 구현계획서

- 작성일: 2026-10-11
- 상태: 구현 전 계획
- 기준: 「할머니 집에서의 별빛 모험.pdf」의 그림과 본문을 나란히 배치한 구성

## 1. 목표와 범위

사용자가 장면별 그림과 글을 입력하면 일정한 페이지 구성으로 미리보기하고 PDF로 내보낸다. 첫 버전은 **왼쪽 그림 + 오른쪽 본문**을 제공한다. 표지, 장면 순서, 페이지 번호, 글꼴과 배경을 설정할 수 있게 한다.

일반 Markdown 문서의 기존 작성·내보내기 기능을 유지하고, 사용자가 그림책 템플릿을 선택한 문서에만 페이지 배치를 적용한다. 빠른 작업 버튼 구성을 관리하는 UI-001과는 별도 기능이다.

### 첫 버전 제공 항목

- 표지: 제목, 부제, 저자, 표지 그림.
- 본문: 장면마다 그림 1개와 Markdown 본문.
- 장면 추가·삭제·순서 변경, 그림 선택·교체.
- 그림 맞춤 방식: 전체 보이기 / 영역 채우기 및 위치 조정.
- 판형·방향: 서식관리에서 선택한 용지 크기와 용지 방향을 사용한다. 페이지 배치는 선택된 용지의 실제 가로·세로 크기에 맞춰 계산한다.
- 배경색, 본문 글꼴·크기·줄간격, 그림과 글의 비율, 페이지 번호.
- 페이지별 미리보기, 넘침 안내, PDF 내보내기.

샘플의 질감 배경·그림자·장식은 별도 디자인 자산으로 준비한다. 장식 없이도 사용할 수 있는 기본 디자인을 먼저 제공한다.

## 2. 사용자 작업 흐름

### 서식관리 통합 방식 — 권장안

그림책 템플릿의 선택·복제·수정·가져오기·내보내기는 **기존 서식관리에서 제공**한다. 별도 템플릿 관리 화면을 만들기보다 서식에 ‘문서 배치’ 설정을 추가한다. 현재 `CssProfile.pageStyle`에는 이미 용지 크기·방향·여백·글꼴·줄간격·배경색이 있으므로 그대로 활용한다.

서식관리 목록에 일반 문서·그림책 분류와 배치 썸네일을 추가한다. ‘새 서식’에서는 기본서식을 선택하여 복제하고, 그림책 서식에서는 다음 설정을 편집한다.

| 설정 영역 | 편집 내용 |
| --- | --- |
| 기본 서식 | 이름·설명, 글꼴·크기·줄간격·색상 |
| 용지 | 기존 용지 크기·방향·여백 설정 |
| 문서 배치 | 일반 문서 / 그림책, 그림 왼쪽·본문 오른쪽 |
| 표지 | 그림 위치, 제목·저자 위치 |
| 장면 | 그림·본문 비율, 영역 간격, 그림 맞춤 방식 |
| 페이지 장식 | 배경, 테두리, 페이지 번호 |
| 샘플 미리보기 | 표지와 본문 페이지의 실제 배치 |

**서식에는 표현 방법을 저장하고, 문서에는 제목·저자·장면·이미지·본문을 저장한다.** 서식을 복제해도 다른 문서의 글과 그림을 함께 복제하지 않는다. 장면 추가·순서 변경은 문서 편집 화면에서 수행한다.

사용 흐름은 ‘문서 열기 → 서식관리 → 그림책 서식 선택 → 현재 문서에 적용 → 장면 편집 → 미리보기 내보내기’로 통합한다. 장면 정보가 없는 기존 문서에는 경계 지정 화면을 보여주고, 원문을 보존한 상태에서 적용 전 배치를 확인한다.

### 데이터 확장안

`CssProfile`에 선택 항목 `layout`을 추가한다. 기존 프로필에 이 항목이 없으면 일반 문서로 처리한다.

```typescript
layout?: {
  schemaVersion: 1;
  type: 'flow' | 'picturebook';
  preset: 'image-left-text-right';
  imageRatio: number; // 그림 영역 비율, 예: 0.5
  gap: string;
  imageFit: 'contain' | 'cover';
  cover: { preset: 'full-image' | 'image-right' };
  pageNumber: { enabled: boolean; position: 'bottom-right' };
};
```

위 정의는 설계 예시이며 구현 시 유형별로 필수 필드를 나누어 검증한다. 용지·방향·여백은 기존 `pageStyle`을 사용하여 같은 설정을 두 곳에 저장하지 않는다. 본문 태그 서식은 기존 `rules`를 사용하고, 장면 그림의 영역 배치는 `layout`을 우선한다. 사용자 CSS가 페이지 영역 밖으로 내용을 밀어내면 경고한다.

기존 `profiles/userCssProfiles.json` 저장·동기화 경로에 확장 프로필을 저장한다. `normalizeCssProfile`, JSON 가져오기·내보내기, AI 서식 생성의 검증 규칙에서도 `layout`이 누락되지 않도록 함께 수정한다. 구버전 앱에서 배치를 지원하지 못하면 해당 서식의 적용을 안내하고, 데이터를 일반 서식으로 덮어쓰지 않도록 호환성 처리를 설계한다.

문서에는 적용 시점의 서식 설정과 버전을 보관한다. 이후 서식관리에서 원본 서식을 수정하면 ‘현재 문서에 업데이트 적용’을 선택하게 하여 기존 책의 배치가 자동 변경되지 않도록 한다. 배경 이미지 등 디자인 자산은 리소스 폴더에 저장하며, 다른 기기로 서식을 내보낼 때는 JSON과 자산을 묶은 패키지 전송 기능이 필요하다. 첫 버전의 JSON 단독 내보내기는 색상 기반 서식과 기본 내장 자산을 우선 지원한다.

1. 새 문서작성에서 저장할 드라이브·폴더·파일 이름을 지정한다.
2. 서식관리에서 ‘그림책’ 분류의 서식을 선택한다.
3. 표지 정보를 입력한다.
4. 장면을 추가하고 그림과 본문을 입력한다.
5. 페이지 미리보기에서 그림 잘림, 본문 넘침, 여백을 확인한다.
6. 문서를 저장하고 PDF로 내보낸다.

기존 문서에서는 ‘템플릿 적용’으로 진입한다. 본문을 임의로 장면으로 분할하지 않고, 사용자가 장면 경계를 확인하도록 한다. 편집 화면에는 장면 목록과 현재 장면의 그림·본문 입력 영역을 제공하며, Markdown 원문 편집도 사용할 수 있게 한다.

## 3. 문서와 템플릿 저장 구조

### 문서

원고는 기존처럼 MD 파일로 저장한다. 문서에는 템플릿 ID·버전, 판형, 표지 정보 및 장면 데이터를 포함한다. 이미지는 기존 로컬 리소스 폴더 또는 Google Drive 참조 폴더에 저장하고 MD에는 참조만 기록한다. Base64 이미지를 새로 본문에 넣지 않는다.

장면 문법은 일반 구분선 `---`와 충돌하지 않도록 명시적인 블록으로 설계한다. 다음은 제안 문법이며, 구현 시 파서와 편집기 양쪽에서 검증한다.

```markdown
---
onrivi_document_type: picturebook
onrivi_template: picturebook-image-left
onrivi_template_version: 1
onrivi_paper: letter-landscape
title: 할머니 집에서의 별빛 모험
author: 작가 이름
---

:::scene {#scene-01}
![장면 설명](media/scene-01.png)

할머니 집에 도착하니 창밖으로 작은 별이 반짝였습니다.
:::
```

장면 블록의 첫 이미지를 장면 그림으로 사용하고, 나머지를 본문으로 해석한다. 추가 이미지 등 첫 버전에서 지원하지 않는 내용은 안내한다. 메타데이터는 본문에 출력하지 않는다. 새 문법 지원을 위해 전용 파서 또는 remark 확장 기능을 추가한다.

기존 이미지 URL과 로컬·Drive 참조 방식은 기존 해석기를 사용한다. 로컬↔Drive 전송 시 장면 속 이미지도 기존 참조 자료 전송 기능에서 인식하고 경로를 바꾸도록 연결한다.

### 템플릿

템플릿은 버전이 있는 JSON 정의와 디자인 자산으로 구성한다.

| 항목 | 내용 |
| --- | --- |
| 식별 | ID, 이름, 버전, 설명, 썸네일 |
| 페이지 | 판형, 방향, 여백, 그림·본문 영역 비율 |
| 표지 | 제목·저자·그림 영역 배치 |
| 서식 | 글꼴, 크기, 줄간격, 배경, 페이지 번호 |
| 그림 | 맞춤 방식, 기본 위치, 모서리 |
| 검증 | 본문 넘침 정책, 지원 콘텐츠 종류 |

기존 서식 프로필의 글꼴·색상 설정과 새 `layout`의 페이지 배치를 한 서식으로 관리한다. 배치 렌더러는 앱 코드에서 제공한다. 템플릿에 실행 코드나 임의 스크립트를 저장하지 않는다. 문서에 적용된 설정을 함께 저장해 기본 템플릿이 수정되어도 기존 책의 모양이 갑자기 바뀌지 않게 한다.

첫 버전은 앱에 기본 템플릿을 포함한다. 관리자에서 템플릿 작성·게시·버전 관리 및 사용자 템플릿 공유 기능은 후속 단계로 진행한다.

미리보기와 PDF는 같은 페이지 렌더러를 사용한다. 화면의 확대·축소는 표시 배율만 바꾸고 실제 페이지 크기는 고정한다. 기존 PDF 변환의 일반 이미지 크기 제한과 페이지 나눔 CSS가 그림책의 고정 영역을 변경하지 않도록 내보내기 경로를 구분한다.

## 5. PDF 출력과 품질 관리

### 데스크탑

현재 Electron의 Chromium PDF 출력 경로를 활용한다. 페이지 크기와 방향을 지정하고, 글꼴 로딩과 이미지 디코딩이 끝난 다음 출력한다. 본문을 실제 텍스트로 출력하여 선택·검색할 수 있는 PDF를 목표로 검증한다.

### 웹

웹 그림책 PDF는 **브라우저 인쇄 → PDF로 저장** 방식으로 구현한다. 전용 인쇄 화면에 공통 페이지 렌더러를 연결하고 용지 크기·방향·배경·페이지 나눔을 반영한다. 현재 코드에는 html2canvas/jsPDF 기반 출력 경로도 있으므로 실제 연결 지점을 확인하여 그림책 출력은 브라우저 인쇄 경로를 사용하도록 한다. 별도 서버 PDF 생성은 이번 범위에 포함하지 않는다.

### 본문 넘침

- 글꼴과 이미지 준비 후 실제 페이지 영역을 측정한다.
- 넘친 장면을 목록과 미리보기에서 표시한다.
- 사용자가 글을 줄이거나 장면을 나누거나 서식을 조정할 수 있게 한다.
- 자동으로 작은 글씨로 축소하거나 본문을 잘라 출력하지 않는다.
- 이미지 로딩 실패와 본문 넘침이 남으면 내보내기 전에 수정하도록 안내한다.

첫 버전의 EPUB은 그림책 PDF와 동일한 배치를 보장하지 않는다. 고정 배치 EPUB은 별도 개발 범위로 잡고, DOCX/HWPX는 기존 본문 변환과 그림책 배치 재현을 구분해 안내한다.

## 6. 단계별 작업과 예상 공수

아래는 현재 코드 구조를 기준으로 한 **개발자 1명 예상치**이며, 실제 착수 시 웹 PDF 방식과 화면 범위를 확정한 후 조정한다.

| 단계 | 작업 | 예상 |
| --- | --- | --- |
| 1 | 문서 문법·템플릿 스키마·판형·예시 원고 확정 | 1~2일 |
| 2 | 장면 파서, 기본 템플릿, 페이지 렌더러 | 2~3일 |
| 3 | 표지·장면 편집, 템플릿 선택, 저장·복원 | 3~4일 |
| 4 | 넘침 검사, 이미지 준비, 데스크탑 PDF | 2~3일 |
| 5 | 웹 인쇄 화면, 로컬·Drive 참조 전송 검증 | 1~3일 |
| 6 | 대표 문서 검증과 수정 | 1~3일 |
| 합계 | 첫 버전 | **10~18 작업일** |

서식관리 통합을 포함하면 분류·설정 폼·프로필 호환성·동기화 검증에 약 2~4 작업일을 추가하여 **총 12~22 작업일**로 예상한다. 별도 템플릿 관리 화면을 만드는 공수는 제외한다.

관리자 템플릿 관리, 고정 배치 EPUB, 웹 서버 PDF 생성은 위 예상에 포함하지 않는다. 전체 완성 전에 장면 2~3개로 미리보기·PDF 시제품을 만들어 페이지 구성부터 확인한다.

## 7. 완료 기준

- 표지와 장면별 페이지 수·순서가 미리보기 및 PDF에서 일치한다.
- 짧은 글·긴 글·한글·영문·목록·인용문이 지정된 영역에서 표시된다.
- 가로·세로 그림의 전체 보기와 영역 채우기가 정상 동작한다.
- 글꼴 로딩 지연, 이미지 실패, 본문 넘침을 확인할 수 있다.
- 데스크탑 PDF에서 한글 텍스트 선택·검색과 페이지 크기를 확인한다.
- 저장 후 다시 열어 장면 순서·설정·이미지가 복원된다.
- 로컬↔Drive 전송 후에도 이미지 참조가 유지된다.
- 일반 Markdown 문서의 미리보기·PDF 내보내기가 기존대로 동작한다.
- 기존 서식을 읽고 저장해도 설정이 손실되지 않으며, 그림책 서식 복제·JSON 왕복·로컬 및 Drive 복원이 정상 동작한다.
- 서식 변경 시 문서 내용이 유지되고, 기존 문서에 새 서식을 적용할 시점을 선택할 수 있다.

## 8. 착수 시 확정할 사항

1. **확정:** 서식관리에서 용지 크기와 용지 방향을 선택한다. 미리보기와 PDF 내보내기는 해당 설정을 공통으로 사용하며, 변경 후 본문 넘침을 다시 검사한다.
2. **확정:** 표지 배치가 다른 기본 서식 두 가지를 제공한다. ‘그림책 — 전체 그림 표지’와 ‘그림책 — 오른쪽 그림 표지’로 구분하며, 본문은 공통으로 왼쪽 그림·오른쪽 본문을 사용한다. 내부적으로 공통 배치 렌더러를 사용하고 표지 설정만 다르게 저장한다.
3. **확정:** 웹 PDF는 브라우저 인쇄의 ‘PDF로 저장’ 방식을 사용한다. 별도 서버 생성은 포함하지 않는다.
4. **글꼴 확정:** 사용자 설명에 따라 현재 사용 중인 OS 제공 글꼴과 상업적 이용이 가능한 무료 글꼴을 활용한다. 새로운 글꼴 도입은 이번 범위에 포함하지 않는다. OS 글꼴 파일을 서식 패키지에 복사하지 않고 글꼴 이름을 참조한다. 출력 전 글꼴 준비 상태와 대체 글꼴 적용 여부를 확인한다. 배경은 기본 색상을 우선 제공하고 그림 배경은 기존 사용 가능한 자산 또는 사용자가 지정한 이미지로 설정한다.

이 문서는 구현계획서이며, 그림책 템플릿 기능은 아직 적용하지 않았다.
