# 온리비 페이지 나누기·워터마크 구현계획서

작성일: 2026-10-19  
상태: 1차 소스 구현 및 검증 완료, 배포·설치본 빌드 전  
적용 대상: 웹·데스크톱의 일반 문서보기와 인쇄/PDF 출력

## 1. 목표와 확정 원칙

1. 일반 문서를 종이 단위로 확인하고, 페이지별 글·그림 배치를 판단할 수 있게 한다.
2. 내용이 늘면 자동으로 페이지가 증가하며, 원하는 위치에 수동 페이지 나누기를 넣을 수 있게 한다.
3. 문자 또는 이미지 워터마크를 페이지마다 표시하고 PDF에 포함한다.
4. **용지 크기·방향·여백은 현재 문서에 적용된 서식관리 값을 단일 기준으로 사용한다.** 별도의 출력 용지 설정을 중복 관리하지 않는다.
5. 원고는 하나의 마크다운 문서로 유지한다. 자동 페이지 경계는 원고에 삽입하지 않는다.
6. 문서보기와 PDF는 동일한 본문 스타일·페이지 계산·자원 해석 규칙을 사용한다.
7. 기존 문서의 본문과 메타정보를 보존하며 실행 취소, 한글 입력, 커서 이동, 드롭 기능을 유지한다.

## 3. 적용 범위

### 이번 구현

- 일반 문서의 자동 페이지 경계·페이지 번호·총 페이지 수 표시
- 수동 페이지 나누기 삽입·선택·삭제·실행 취소
- 서식 변경 및 내용 변경에 따른 재계산
- 문자·이미지 워터마크 중 하나를 선택하여 적용
- 워터마크 위치·크기·투명도·각도 및 첫 페이지 제외 설정
- 로컬·브라우저 보관함·구글 드라이브 리소스 지원
- 문서 설정 저장 및 다시 열기
- 웹 인쇄/PDF와 데스크톱 PDF 검증

### 후속 범위

- 그림책의 기존 장면별 페이지에 워터마크를 적용하는 기능
- 여러 워터마크 동시 적용, 바둑판 반복, 페이지별 서로 다른 이미지
- PDF 서명·암호화·변조 방지 기능
- DOCX·EPUB 등 다른 형식의 워터마크

워터마크는 시각적인 표시다. 문서 복사·변조를 막는 보안 기능으로 안내하지 않는다.

## 4. 사용자 화면

### 4.1 페이지 보기

- 보기 메뉴에 **페이지 구분 보기** 켜기·끄기 제공
- 켜면 종이 사이 간격과 페이지 번호 표시
- 상태 영역에 현재 용지·방향과 전체 페이지 수 표시
- 용지·방향·여백을 바꾸려면 기존 **서식관리**로 이동
- 화면 확대·축소는 페이지의 표시 크기만 변경하며 실제 페이지 수를 바꾸지 않음
- 페이지 구분 표시는 보기 설정으로 보존하며 문서 본문에 저장하지 않음

### 4.2 수동 페이지 나누기

- 삽입 메뉴 및 `/페이지 나누기` 명령 제공
- 문단 중간에서 실행하면 해당 문단을 둘로 나누고 뒤쪽 내용을 다음 페이지에서 시작
- 문서보기에는 ‘페이지 나누기’ 경계를 표시하며 출력에는 안내 문구를 숨김
- 경계를 선택한 Delete 또는 경계 앞뒤의 정해진 Backspace/Delete 동작으로 제거
- 삽입·삭제는 한 번의 실행 취소로 복구
- 일반 구분선 `---`의 의미는 유지
- 표 내부에서는 표를 임의로 절단하지 않고 표 앞·뒤 삽입 위치를 안내
- 중첩 목록 안의 삽입은 목록을 보존하는 분할 규칙을 검증한 뒤 허용하고, 초기에는 목록 바깥 경계로 제한
- 문서 시작·끝 또는 연속된 나눔으로 생기는 빈 페이지는 기본적으로 억제. 의도적인 빈 페이지 삽입은 후속 기능으로 분리

### 4.3 워터마크

내보내기 화면에서 **인쇄/PDF 설정 → 워터마크** 제공.

| 항목 | 계획 |
| --- | --- |
| 기본 상태 | 사용 안 함 |
| 종류 | 문자 / 이미지 |
| 문자 | 초안·검토용·저자명 등 사용자 입력 |
| 이미지 | PNG·JPG·WebP, 투명 PNG 권장 |
| 위치 | 가운데·좌상단·우상단·좌하단·우하단 |
| 크기 | 문자 크기 또는 이미지 너비 비율, 이미지 비율 유지 |
| 진하기(불투명도) | 0~100%, 초기 15% 제안. 0%는 보이지 않고 100%는 완전히 진하게 표시 |
| 회전 | -90~90도, 문자 초기 -30도·이미지 초기 0도 제안 |
| 적용 페이지 | 전체 / 첫 페이지 제외 |
| 미리보기 | 현재 설정으로 페이지별 확인 |

설정은 실제 내보내기 전에 사용자가 확인할 수 있어야 한다. 이미지 없음·읽기 실패·투명도 0%는 화면에서 명확히 안내한다.

## 5. 공통 페이지 계산

### 5.1 서식관리 값 사용

공통 `resolvePageGeometry` 모듈을 신규 작성한다.

입력: 현재 문서의 유효 CssProfile 및 pageStyle.  
출력: 용지 너비·높이, 본문 너비·높이, 여백, 방향, 인쇄용 CSS.

- 표준 용지 규격을 mm로 변환
- 가로 방향에서는 너비·높이를 한 번만 교환
- 상하좌우 여백을 반영하여 실제 본문 공간 계산
- 단위 변환과 브라우저 측정은 한곳에서 처리
- 알 수 없는 용지·음수 여백·본문 공간이 0 이하인 설정은 검증 오류 또는 공식 기본값으로 처리하고 사용자에게 안내
- 사용자 지정 용지는 현재 서식 데이터가 지원하는 범위를 먼저 확인한 뒤 반영
- 기본 서식·사용자 서식·문서 전용 서식에도 동일 함수 적용

### 5.2 자동 분할

렌더링된 글꼴·글자 크기·줄 간격·문단 여백·그림·표 높이를 기준으로 계산한다.

- 짧은 제목은 뒤 본문과 함께 이동
- 그림과 캡션은 가능한 한 같은 페이지에 배치
- 큰 그림은 비율을 유지하며 한 페이지에 맞춤
- 표는 가능한 한 행 단위로 분할하고 머리글 반복 여부 검증
- 한 페이지보다 큰 표 행·코드·인용문은 별도의 넘침 처리 규칙 적용
- 각주·참고문헌·목록·수식이 존재하는 문서를 별도 검증
- 일반 문서의 기존 각주 배치 방식은 유지. 페이지별 하단 각주를 새로 만드는 작업은 포함하지 않음

### 5.3 화면과 출력의 일치 전략

고정 간격으로 선만 긋는 방식은 실제 인쇄 경계와 달라질 수 있으므로 최종 구현으로 사용하지 않는다.

1. 편집 가능한 원고와 별도의 측정용 렌더링 영역을 둔다.
2. 측정 영역에 동일 서식·폰트·이미지를 적용하고 로딩 완료 후 페이지를 계산한다.
3. 공통 페이지 결과로 문서보기의 경계와 출력 HTML을 구성한다.
4. 원래 편집 DOM을 매번 재생성하지 않고, 표시용 레이어와 페이지 미리보기를 갱신한다.
5. 실제 PDF의 경계와 비교하여 일치 범위를 검증한다.

실제 줄·표 분할을 지원할 수 있는 페이지 구성 방식은 1단계에서 기술 검증 후 확정한다. 단순 높이 누적으로는 복잡한 표와 문단 중간 분할을 정확히 처리할 수 없다.

편집 DOM을 분할하지 않고 정확한 빈 공간을 표현하기 어려우면, 먼저 **완성본 페이지 미리보기**를 제공하고 편집 화면에는 예상 경계임을 표시한다. 검증되지 않은 경계를 실제 인쇄 경계로 안내하지 않는다.

### 5.4 재계산과 성능

- 입력 종료 후 짧은 지연을 두고 재계산하며 한글 조합 중에는 레이아웃 재배치를 보류
- 이미지 로딩, 폰트 로딩, 용지·방향·여백 변경, 수동 나눔 변경 시 재계산
- 빠른 연속 변경에서는 이전 계산 결과를 폐기
- 확대·축소 시 문서 좌표와 화면 좌표를 구분
- 표시 갱신 중 커서·선택·스크롤 기준 위치를 보존
- 긴 문서의 전체 재계산을 줄이고, 초기에는 정확성 확보 후 변경 구간 최적화

## 6. 마크다운 및 설정 저장

### 6.1 수동 페이지 나누기

전용 표식으로 단독 행의 `<!-- onrivi:page-break -->`를 제안한다.

- 파서에서 전용 페이지 나눔 노드로 인식
- 앞뒤 본문·목록·이미지를 하나의 보호 블록으로 묶지 않음
- 저장·다시 열기·복사·붙여넣기 시 유지
- 코드 블록과 인라인 코드 안의 동일 문자열은 문자로 유지
- 다른 마크다운 도구에서는 주석으로 보이며, 그 도구의 페이지 분할까지 보장하지는 않음

### 6.2 워터마크

문서별 출력 설정으로 저장한다. 공용 서식 프로필을 바꿔 다른 문서에 워터마크가 전파되지 않게 한다.

- 버전이 있는 설정 구조 사용
- 기존 Frontmatter·css_profile·문서 메타정보 보존
- 사용 여부, 종류, 문구/이미지 참조, 위치, 크기, 투명도, 각도, 첫 페이지 제외 저장
- 이미지 바이너리는 마크다운 메타정보에 넣지 않고 현재 리소스 폴더의 이미지 저장 흐름 사용
- 기존 메타 파서가 단순 키-값 형식이므로, 검증된 단일 설정 값 또는 명시적인 평면 키 방식을 선택. 중첩 YAML을 현재 파서에 그대로 추가하지 않음
- 설정 변경·취소·저장·실행 취소 정책을 일관되게 적용

## 7. 이미지 워터마크 자원 처리

1. 사용자가 이미지를 선택한다.
2. 기존 리소스 저장 기능으로 로컬·브라우저 보관함·구글 드라이브에 저장한다.
3. 문서에는 상대 참조와 워터마크 설정을 기록한다.
4. 출력 전 실제 파일을 읽어 인쇄 HTML에 포함 가능한 형태로 변환한다.
5. 외부 네트워크 접근 없이 PDF를 만들 수 있도록 준비한다.

검증 사항:

- 허용된 이미지 형식·크기·픽셀 수 제한 및 실제 디코딩 확인
- 최초 범위에서 SVG·HTML 등 실행 가능한 형식 제외
- 폴더·계정 변경 후 이전 계정 자원을 잘못 읽지 않음
- 파일 이동·삭제·드라이브 만료 시 실패 사유 안내
- 워터마크를 적용하지 못하면 조용히 누락한 채 출력하지 않음
- 이미지 교체 시 이전 이미지를 자동 삭제하지 않음

## 8. 워터마크 렌더링과 출력

- 워터마크는 본문 공간을 차지하지 않는 페이지별 전용 레이어로 표시
- 그림 위에도 보이도록 낮은 투명도의 전경 레이어를 기본으로 검토하며, 글·그림의 가독성을 실제 출력으로 확인
- 선택·드래그·커서 이동을 방해하지 않도록 표시 레이어의 포인터 이벤트 차단
- 페이지마다 회전·위치 계산이 독립적으로 적용되도록 구성
- 문자 입력은 HTML로 해석하지 않고 텍스트로 삽입
- 문서보기의 워터마크 미리보기는 켜고 끌 수 있지만 출력 설정 자체는 유지
- 첫 페이지 제외는 섹션이 아닌 전체 문서의 실제 페이지 번호 기준

### 웹

현재 브라우저 인쇄 흐름에 공통 페이지 HTML을 전달한다. 인쇄와 ‘PDF로 저장’은 같은 경로이므로 워터마크 사용 여부는 인쇄 창을 열기 전에 선택한다.

브라우저 인쇄 창에서 사용자가 용지·배율·여백을 바꾸면 화면과 결과가 달라질 수 있다. 지원 브라우저별로 CSS 용지 규격의 적용 상태를 검증하고, 필요한 출력 조건을 안내한다.

### 데스크톱

현재 `printHTMLToPDF`에 같은 페이지 HTML과 용지 규격을 전달한다. 이미지·글꼴 준비 완료 후 생성하며 배경 출력과 한글 문자를 검증한다.

웹과 데스크톱 모두 페이지 수·순서·워터마크 반복 여부를 실제 생성된 PDF에서 확인한다. 단순히 HTML에 워터마크가 존재하는 것으로 검증을 끝내지 않는다.

## 9. 구현 단계와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 | 현재 출력 회귀 기준 수집, 공통 용지 계산, 페이지 구성 기술 검증 | A4 세로·가로 등에서 화면/PDF 경계 차이를 측정하고 구현 방식 확정 |
| 2 | 수동 나눔 파서·노드·명령·키보드·저장 | 삽입·삭제·실행 취소·다시 열기와 PDF 반영 통과 |
| 3 | 자동 페이지 모델·완성본 미리보기·경계 표시 | 내용·서식 변경 시 페이지 자동 증가/감소, 글·그림 누락 없음 |
| 4 | 문자 워터마크 설정·미리보기·출력 | 모든 페이지/첫 페이지 제외, 한글·특수문자·투명도 통과 |
| 5 | 이미지 워터마크 저장·참조·출력 | 각 저장 환경에서 다시 열기 및 실제 PDF 표시 통과 |
| 6 | 통합·성능·배포 준비 | 웹·데스크톱 회귀 검증, 사용 안내와 변경 내역 작성 |

단계 1의 기술 검증 이후 실제 일정과 세부 작업량을 확정한다. 정확한 페이지 편집을 문자 워터마크와 같은 난이도로 산정하지 않는다.

## 10. 필수 검증 시나리오

### 페이지

- 서식관리의 A4/A5, 세로/가로, 서로 다른 여백
- 용지·방향 변경 후 수동 나눔 유지와 자동 페이지 수 재계산

- 문단 중간·문서 시작·끝·연속 나눔, 삽입/삭제 실행 취소
- 저장·다시 열기·원문과 문서보기 왕복 후 위치 보존
- 한글 조합, 커서 이동, 다중 선택, 이미지 드롭, 스크롤 흔들림 회귀
- 화면 확대 배율 변경으로 실제 페이지 수가 달라지지 않음

- 사용 안 함에서 기존 출력 유지
- 한글·영문·따옴표·HTML처럼 보이는 문자
- 투명 PNG·JPG·WebP와 손상된 이미지
- 가운데·모서리·회전·투명도, 용지 경계 잘림
- 모든 페이지/첫 페이지 제외와 수동 나눔 조합
- 그림이 페이지를 크게 차지하는 문서의 가독성
- 리소스 미연결·이미지 누락·구글 드라이브 만료
- 문서별 설정 분리 및 기존 Frontmatter 보존
- 웹·데스크톱의 실제 PDF에서 매 페이지 확인

### 성능

- 짧은 문서와 10·50·100페이지 규모의 문서를 비교
- 폰트·이미지가 늦게 로딩되는 조건
- 연속 입력·빠른 서식 변경 중 오래된 계산 결과가 화면을 덮지 않음
- 원문 내용·파일 저장·활성 탭 상태가 페이지 계산 때문에 변경되지 않음

- 쪽 윤곽과 인쇄/PDF가 동일한 조판 결과를 사용한다. 웹 인쇄 창의 사용자 변경까지 통제하지는 않는다.

- 검증 스크립트: `scripts/check-pagination-watermark.cjs`, `scripts/check-visual-editor.cjs --visual --page-break-only`, `scripts/check-list-marker-editing.cjs` 및 프런트엔드 타입 검사.

## 13. 추가 제안 검토 및 반영 사항

검토 기준: 사용자가 전달한 ‘워터마크 / 강제 쪽 나눔 / 실시간 쪽 윤곽’ 비교 설명.

### 13.1 기능 이름과 사용자 안내

세 기능을 화면과 안내서에서 분명히 구분한다.

| 화면 명칭 | 의미 | 원고에 저장되는 것 |
| --- | --- | --- |
| 페이지 구분 보기 | 자동으로 계산한 페이지 경계를 보여주는 보기 방식 | 자동 경계는 저장하지 않음 |
| 페이지 나누기 삽입 | 사용자가 지정한 위치에서 새 페이지 시작 | 수동 나눔 표식 |
| 워터마크 | 출력물의 상태·작성자·배포 주의 문구 또는 이미지 표시 | 문서별 워터마크 설정과 이미지 참조 |

‘실시간’은 입력 중 편집 영역을 계속 재배치한다는 의미로 사용하지 않는다. 한글 입력이 끝나고 페이지 계산이 갱신되는 짧은 지연을 허용하며, 계산 중에는 이전 결과와 갱신 상태를 표시한다.

### 13.2 두 가지 페이지 표시 방식

- **경계선 보기:** 기존 연속 문서에 계산된 경계와 페이지 번호를 표시. 정확한 인쇄 분할을 재현하지 못한 단계에서는 ‘예상 경계’로 안내.
- **쪽 윤곽 미리보기:** 회색 바탕 위에 용지별 카드와 페이지 사이 간격을 표시. 완성본 배치 확인에 사용.

두 화면이 서로 다른 페이지 계산을 하지 않도록 공통 페이지 모델을 사용한다. 초기 구현은 경계선 보기와 읽기 전용 쪽 윤곽 미리보기를 제공하고, 독립 카드 안에서 직접 편집하는 기능은 입력·선택 안정성 검증 후 확장한다.

### 13.3 용지 높이 설명 정정

‘A4 한 장의 상하 여백 제외 높이가 약 1,123px’라는 설명은 정정한다.

- 96 CSS px/in 환산에서 약 1,123px는 A4 세로 용지 **전체 297mm 높이**다.
- 실제 본문 높이는 `(용지 높이 - 위 여백 - 아래 여백)`으로 계산한다.
- 예를 들어 A4 세로, 위·아래 여백 각각 18mm이면 본문 높이는 261mm, 약 986 CSS px다.
- 가로 방향·다른 용지·다른 여백에서는 다시 계산하며 고정된 A4 픽셀 값을 사용하지 않는다.
- 화면 표시 배율과 장치 픽셀 밀도를 실제 문서 규격과 혼동하지 않는다.

### 13.4 단축키 충돌 방지

현재 문서 편집기의 Ctrl+Enter는 표·코드·인용문·이미지 등 블록에서 빠져나오는 동작에 사용된다.

- 페이지 나누기에 Ctrl+Enter를 일괄 재지정하지 않는다.
- 1차 구현은 삽입 메뉴와 `/페이지 나누기`를 제공한다.
- 단축키는 기존 사용자 설정과 충돌을 확인한 뒤 별도 지정 또는 사용자 지정으로 제공한다.
- 명령 실행 후 커서는 다음 페이지의 편집 가능한 본문 위치로 이동해야 한다.

### 13.5 제목 기준 자동 나눔은 선택 기능

‘H1마다 새 페이지’는 내용이 용지를 채워 생기는 자동 나눔과 별도의 규칙이다.

- 기본값은 사용 안 함으로 유지한다.
- 후속 선택 항목으로 ‘제목 1에서 새 페이지’ 등을 검토한다.
- 기존 exportPageBreakLevel 필드가 있다는 이유만으로 과거 동작을 자동 복원하지 않는다.
- 수동 나눔과 제목 규칙이 같은 위치에 겹치면 새 페이지는 한 번만 만든다.
- 문서의 첫 제목에는 불필요한 앞쪽 빈 페이지를 만들지 않는다.

### 13.6 수동 나눔 표식 호환성

기본 저장 표식은 `<!-- onrivi:page-break -->` 하나로 통일한다.

- 전달된 제안의 `<!-- [page-break] -->` 및 `<hr class="page-break">`는 가져오기 호환 대상으로 검토한다.
- 전용 표식이 아닌 일반 주석·일반 hr는 임의로 페이지 나누기로 바꾸지 않는다.
- HTML 변형은 문자열 단순 치환 대신 속성·문맥을 검사한다.
- 코드 예제 안의 표식은 실제 나눔으로 해석하지 않는다.
- 호환 표식 정규화는 해당 문서를 실제 수정·저장할 때 수행하며 원문 보존 정책과 맞춘다.

### 13.7 워터마크 설명 및 설정 기준

- ‘무단 복제를 막는다’ 대신 ‘작성자·배포 조건·검토 상태를 표시한다’고 설명한다.
- 출력 워터마크는 문서별 내보내기 설정에서 관리하며, 공통 환경설정에 문구를 입력한 것만으로 모든 문서에 적용하지 않는다.
- 문서보기의 워터마크 표시 여부와 PDF에 포함할지 여부를 구분해 안내한다.
- ‘투명도’와 CSS opacity의 반대 의미로 인한 혼동을 피하려고 조절 항목을 **진하기(불투명도)**로 표시한다. 초기 진하기 15%는 opacity 0.15를 뜻한다.
- 본문 뒤에만 그리면 불투명한 그림·표 배경에 가려질 수 있다. 초기 기본은 낮은 진하기의 전경 레이어로 검증하고 ‘배경 표시’는 별도 선택 범위로 판단한다.
- 문자 각도 45도를 강제하지 않는다. 문자·로고·도장의 용도에 따라 사용자가 조절한다.

### 13.8 EPUB 범위 구분

EPUB은 독자의 화면·글자 크기·리더 설정에 따라 페이지가 바뀌므로 A4 페이지 경계를 보장하지 않는다.

- 이번 기능의 출력 일치 검증 대상은 인쇄/PDF다.
- EPUB의 수동 나눔 처리는 향후 장·섹션 구분 의미로 별도 설계한다.
- PDF와 동일한 물리적 페이지 번호·쪽 경계·페이지별 워터마크를 EPUB에도 보장한다고 안내하지 않는다.

### 13.9 추가 수용 기준

1. 페이지 구분 보기를 끄고 켜도 원고 내용과 수동 나눔 위치가 달라지지 않는다.
2. 용지·방향·여백 변경이 두 가지 페이지 보기와 PDF에 함께 반영된다.
3. 수동 나눔과 제목 규칙이 겹쳐도 빈 페이지가 중복 생성되지 않는다.
4. 단축키 추가로 기존 블록 탈출·한글 입력·사용자 단축키가 깨지지 않는다.
5. 워터마크 미리보기에서 보인 이미지가 PDF에서도 모든 지정 페이지에 나타난다.
6. 웹 인쇄 설정을 사용자가 바꿔 생기는 차이를 기능 결함과 구분할 수 있도록 출력 조건을 안내한다.

결론: 세 기능의 개념 구분과 두 가지 페이지 표시 방식은 계획에 반영한다. 용지 높이·보안 효과·단축키·EPUB 동작·기존 기능의 구현 여부에 관한 설명은 위 기준으로 정정한다.
