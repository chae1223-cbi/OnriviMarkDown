# 온리비 어서 문서보기 AI 편집 및 다중 AI 연동 구현계획서

- 작성일: 2026-10-19
- 상태: 1차 소스 구현 및 자동 검증 완료(2026-10-20). 운영 배포와 설치형 앱 빌드는 미실행. 구현 결과와 제한사항은 14장 참조.
- 목표: 별도의 AI 작성 모달로 이동하지 않고 문서보기의 해당 위치에서 문장을 고치고, 사용자가 선택한 AI 제공자를 이용한다.

## 1. 요구사항과 구현 범위

1. 문서보기에서 선택한 구문 또는 현재 문단을 AI로 수정한다.
2. 첨부한 온리비 AI 버튼을 기본 진입점으로 사용한다. 위쪽은 프롬프트 입력, 아래 모델명은 제공자·모델 변경이다. /명령어도 같은 편집 상태로 연결한다. 플로팅 툴바를 필수 진입점으로 사용하지 않는다.
3. 생성 결과는 해당 문단 근처에 표시하고 사용자가 확인한 뒤 적용한다.
4. Google(Gemini·Gemma), OpenAI, Anthropic(Claude)를 1차 지원하는 공통 구조를 만든다.
5. 웹과 데스크톱에서 같은 편집 경험을 제공한다. 제공자별 연결 가능 여부는 별도 검증한다.
6. 기존 제목·목록·표·링크·이미지·각주·수동 페이지 나누기와 메타정보를 보존한다.
7. 원문은 사용자가 적용하기 전까지 변경하지 않는다.

### 1차 제공 기능

- 맞춤법·문법 교정, 자연스럽게 다듬기, 짧게 줄이기, 쉽게 설명하기, 문체 바꾸기, 번역, 직접 요청.
- 선택한 글 교체, 현재 문단 교체, 현재 문단 아래에 새 문단 삽입.
- 생성 중지, 다시 생성, 수정안 편집, 적용, 취소, 적용 후 한 번에 실행 취소.
- Gemini·Gemma·OpenAI·Claude 텍스트 편집을 모두 첫 출시 목표로 한다. 세 제공자와 네 모델군의 연결·취소·오류·적용 검증을 각각 통과해야 지원으로 표시한다. Google 연결 안에서 Gemini와 Gemma를 구분한다.

### 후속 범위

- Gemma를 포함한 로컬 AI 실행, 사용자 지정 호환 서버, 문서 전체 일괄 교정. Gemma의 Google API 연동과 Claude 연동은 후속이 아닌 1차 범위다.
- 여러 수정안을 차례대로 승인, 표의 여러 셀 편집, 구조 변경을 수반하는 목록 변환.
- 지식보관함 근거를 이용한 작성 및 검증된 인용 삽입.
- 그림책 장면, 이미지 생성·편집, 음성 기능은 별도 단계로 검토한다.

## 3. 문서보기 사용 흐름

### 3.1 선택한 구문 수정

1. 문장 또는 구문을 드래그한다.
2. 온리비 AI 버튼 위쪽을 눌러 프롬프트 입력란을 열고 작업을 고른다.
3. 선택 영역을 강조하고 가까운 위치에 작은 입력·검토 패널을 연다. 전체 화면을 가리는 모달은 사용하지 않는다.
4. 패널에 작업 대상, AI 제공자/모델, 직접 요청 입력칸을 표시한다.
5. 생성 결과는 원문 아래의 검토 영역에 표시한다. 원문을 덮어쓰지 않는다.
6. 사용자가 차이를 확인하고 필요하면 수정안을 편집한다.
7. ‘선택한 글 바꾸기’ 또는 ‘문단 아래에 추가’를 눌러 적용한다.
8. 한 번의 편집 트랜잭션으로 반영하고 실행 취소를 지원한다.

### 3.2 선택 영역이 없을 때

- 현재 일반 문단에서는 ‘이 문단 다듬기’를 제공한다.
- 빈 문단에서는 ‘여기에 작성하기’를 제공한다.
- /AI 명령은 명령 문자열을 제거한 실제 삽입 위치를 먼저 확정한다.
- 문서 끝, 제목, 목록 안에서는 대상 종류를 구분해 사용 가능한 작업을 안내한다.
- 읽기 전용 문서에서는 원문 수정 버튼을 제공하지 않는다.

### 3.3 검토 영역 구성

- 원문 / 수정안 비교, 변경 부분 강조. 색 외에도 삭제·추가 표시를 제공한다.
- 생성 중: 중지. 생성 완료: 바꾸기 / 아래에 추가 / 다시 생성 / 취소.
- 선택한 작업에 맞는 기본 적용 버튼만 우선 노출한다.
- 수정안 내부 편집은 본문과 분리된 임시 편집 상태로 유지한다.
- 패널은 에디터 외부 포털 또는 ProseMirror 장식으로 연결한다. 생성 문자열을 본문 DOM에 직접 삽입하지 않는다.
- 패널 때문에 페이지 경계, 원고 저장, PDF·인쇄, 복사에 임시 결과가 섞이지 않게 한다.
- 긴 결과는 패널 내부를 스크롤하며 본문 스크롤과 커서를 임의 이동하지 않는다.

## 4. 대상 범위와 원문 보호

### 4.1 위치 추적

요청 시작 시 다음 정보를 저장한다.

- requestId, documentId, editorInstanceId, 문서 버전
- 선택 from/to, 원문 조각, 앞뒤 문맥, 대상 노드 종류
- 작업 종류, 제공자·모델, 결과 적용 방식

문서보기는 ProseMirror Transaction.mapping으로 대상을 추적한다. 마크다운 편집기는 Monaco 추적 범위를 사용한다. 단순 문자열 검색으로 같은 문장을 찾아 교체하지 않는다.

- 대상 앞의 편집: 위치만 갱신한다.
- 대상 자체의 수정·삭제 또는 의미가 달라지는 구조 변경: 적용을 막고 재선택을 안내한다.
- 다른 탭으로 이동: 요청을 취소하고 이전 응답은 폐기한다. 대상 문서로 자동 적용하지 않는다.
- 실행 취소/다시 실행, 파일 재열기, 외부 동기화로 문서가 교체될 때도 유효성을 재검사한다.
- 1차는 문서당 동시에 한 요청만 허용한다. 재요청하면 이전 요청·응답을 무효화한다.

### 4.2 서식 보존

| 대상 | 1차 처리 |
|---|---|
| 일반 문단의 일부 텍스트 | 텍스트 구간만 교체. 구간 밖 서식과 형제 노드 유지 |
| 전체 일반 문단 | 텍스트 교정 또는 명시적 아래 삽입. 제목/문단 속성 보존 |
| 제목 | 제목 수준을 유지하고 글자만 수정 |
| 목록 항목 본문 | 항목 하나의 텍스트만 수정. 번호·체크 상태·들여쓰기 유지 |
| 표의 단일 셀 | 텍스트만 수정. 병합·행·열 구조 유지. 후속 검증 후 활성화 |
| 여러 블록/복합 서식 선택 | 초기에는 지원 범위를 안내. 자동 평탄화·전체 교체 금지 |
| 이미지·코드·수식·각주·인용·미디어·페이지 나누기·메타정보 | 기본 편집 대상에서 제외. 후속 기능으로 별도 처리 |

서로 다른 강조·링크 서식이 섞인 부분은 단순 텍스트 대체로 원래 서식 경계를 보장할 수 없다. 1차에서는 균일한 서식 구간으로 제한하고, 혼합 구간은 재선택 안내를 한다. 링크 주소는 AI가 임의 변경하지 않도록 주소를 보호한다.

마크다운 반환은 아래 삽입 등 구조 생성이 필요한 작업에서만 허용한다. 파싱·스키마 검사 후 적용하고 외부 HTML/script/event handler를 실행하지 않는다. 원문에 없는 링크·이미지 경로·각주 참조가 만들어진 경우 자동 승인하지 않는다.

## 5. 공통 AI 계층

### 제안 모듈

- lib/ai/types.ts: 제공자·모델·작업·요청·결과·오류 타입
- lib/ai/providerRegistry.ts: 제공자 등록과 기능 지원표
- lib/ai/providers/gemini.ts, openai.ts, anthropic.ts: 공급사별 요청·스트림 변환
- lib/ai/transports/web.ts, desktop.ts: 실행 환경별 통신·키 취급
- lib/ai/request.ts: 취소·시간 제한·재시도·공통 이벤트
- lib/ai/prompts.ts: 작업별 프롬프트와 문맥 정책
- lib/ai/modelCatalog.ts: 모델 조회·검증·캐시
- lib/ai/editorAdapters/visual.ts, monaco.ts: 대상 캡처·검사·적용
- hooks/useInlineAI.ts: 요청과 검토 상태 관리
- components/ai/InlineAIComposer.tsx, InlineAIReview.tsx: 문서 내 입력·검토
- components/ai/AIConnectionSettings.tsx: 환경설정 내 제공자 관리

공통 이벤트는 start / textDelta / usage / complete / error로 통일한다. 응답 중단, 출력 한도, 거절, 빈 결과는 정상 완료와 구분한다. 일부 토큰이 수신된 요청을 자동 재시도하여 기존 출력에 이어 붙이지 않는다.

전체 흐름: 편집기 대상 캡처 → 필요한 문맥 준비 → 요청 계층 → 제공자 어댑터 → 임시 수정안 → 대상 유효성 검사 → 편집기 단일 트랜잭션 적용.

## 6. 다른 AI 연결 및 환경설정

환경설정의 AI 항목에서 다음을 관리한다.

- 제공자: Google(Gemini·Gemma) / OpenAI / Anthropic(Claude). 구현·검증되지 않은 제공자는 사용 가능으로 표시하지 않는다.
- 연결 이름, 인증 정보, 사용 가능 모델, 기본 모델, 연결 시험, 연결 삭제.
- 작업별 기본 문체·언어와 기본 작업 범위.
- 최근 연결은 계정별로 보관하고 API 키를 문서 메타정보에 기록하지 않는다.
- 기존 Gemini 키와 모델을 이전하되 유효한지 시험하고 실패 시 기존 값을 임의 변경하지 않는다.
- 모델 선택 시 제공자·모델·예상 전송 범위를 표시한다. 비용은 측정 가능한 사용량을 바탕으로 안내하며 고정 요금이나 무료 사용을 보장하지 않는다.

### 키 보관과 실행 환경

- 데스크톱: Electron 메인 프로세스와 OS 보호 저장소를 통해 키를 보관한다. renderer에는 키 대신 연결 식별자를 전달하고 허용된 AI 호출만 IPC로 요청한다.
- 웹 1차: 사용자가 제공한 키는 기본적으로 세션 메모리에만 유지한다. 브라우저 직접 호출이 불가능한 공급사는 인증된 동일 출처 중계 경로를 사용하며, 키는 요청 중에만 전달하고 저장·로그에 남기지 않는다. 통신 경로를 UI에 안내한다.
- 정적 웹 배포에는 서버 중계가 없을 수 있다. 구현 전 호스팅의 서버/함수 지원을 확인하고, 지원되지 않는 연결은 비활성화한다. 공개 프록시로 우회하지 않는다.
- 웹에서 장기 보관을 제공하려면 서버 암호화·계정 권한·삭제·운영 정책을 별도 설계한 뒤 추가한다. 클라이언트의 고정 비밀값으로 암호화한 localStorage를 안전한 키 보관으로 설명하지 않는다.
- 기존 일반 설정 파일·Drive 동기화·백업에 키가 들어가는 경로를 제거한다. 기존 값 삭제는 새 보관소로의 이전 성공을 확인한 뒤 수행한다.
- 사용자 지정 서버는 후속 지원한다. 서버 주소 허용 정책, 인증 헤더, CORS, SSRF 및 로컬 네트워크 접근 범위를 검토한 뒤 활성화한다.

## 7. 문맥·지식·개인정보

- 기본 전송 범위는 선택한 글과 필요한 주변 문맥이다. 문서 전체 자동 첨부는 끈다.
- 최대 입력·출력 한도를 지정하고 초과 시 알린다. 문서를 조용히 잘라 보내지 않는다.
- 지식보관함 연결은 기본 끔. 켠 경우 검색된 문서·전송 범위를 확인할 수 있게 한다.
- 문서 안의 지시문과 사용자의 편집 요청을 분리한다. 문서 내용은 편집할 자료로 전달한다.
- 주민등록번호·계좌번호 등 민감정보 감지 시 마스킹 옵션을 제공한다. 탐지가 완벽하다고 보장하지 않는다.
- 로그에는 요청 ID, 제공자·모델, 길이, 소요시간, 오류 코드만 남긴다. 키·원문·생성 결과는 기본 기록하지 않는다.
- AI가 제시한 출처를 실재 근거로 간주하지 않는다. 지식 검색으로 확인된 문서 식별자만 실제 인용으로 연결한다.
- 부동산 매매 서류 같은 분야는 공식 출처·확인일·적용 조건을 별도 데이터로 관리해야 한다. 범용 생성 모델만으로 필수 서류를 확정하거나 공적 증명서를 생성하는 기능은 이번 범위에 포함하지 않는다.

## 10. 출시 및 도움말

- 기존 AI 작성 모달은 전환 기간 동안 유지한다. 새 문서보기 AI가 안정화되면 진입점을 정리한다.

- 새 기능은 초기 비활성 플래그로 검증하고, 지원 제공자와 편집 범위를 도움말에 명시한다.
- 검토 완료 후 웹 배포와 데스크톱 빌드·설치는 별도 진행한다.
- 성공 기준: 사용자가 문서보기에서 글을 선택해 AI 수정안을 확인하고, 원문 주변을 손상하지 않은 채 적용·취소할 수 있다.

## 11. 최신 모델·API 지원 개정 (2026-10-19)

사용자 요청에 따라 Gemini·Gemma·OpenAI·Claude를 모두 1차 지원 범위로 확정한다. 아래 모델은 공식 문서 확인 시점의 후보이며 사용자의 키로 연결 검증을 거친 후 선택 가능하게 한다. 추후 출시되는 모델은 목록 갱신으로 발견할 수 있게 하되 새로운 API 기능까지 앱 업데이트 없이 자동 지원한다고 보장하지 않는다.

### 11.1 제공자·모델·API 구성

| 설정 화면 | 모델군 및 확인된 후보 | 통신 방식 | 출시 조건 |
|---|---|---|---|
| Google → Gemini | 공식 목록의 최신 텍스트 생성 모델. 확인 후보 `gemini-3.8-flash` 및 계정에 제공되는 더 최신 모델 | 권장 Google GenAI SDK `@google/genai`, generateContent/스트리밍 | 목록 조회, 텍스트 출력·스트리밍·중지·문서 적용 시험 |
| Google → Gemma | Gemma 4 계열. 공식 API 예시 `gemma-4-26b-a4b-it`; 그 밖의 실제 제공 모델 | 동일 Google API 연결을 재사용하고 모델군을 Gemma로 분류 | 해당 계정·지역·할당량·모델 기능 확인. Gemini와 지원 옵션이 같다고 가정하지 않음 |
| OpenAI | GPT-6.1 Sol, GPT-6 Astra, GPT-6 Luna 등 공식 모델 목록의 현행 텍스트 모델 | Responses API 및 공식 SDK, Models 목록 조회 | 목록 접근만으로 생성 가능이라 단정하지 않고 실제 Responses 연결 확인 |
| Anthropic → Claude | Claude Sonnet 5.5, Opus 5.5, Haiku 5.5, Fable 5.1 등 공식 현행 목록 | Messages API 및 공식 SDK, Models API | 모델별 실제 접근·스트리밍·취소·완료 사유 확인 |

Gemma는 Gemini 모델의 다른 이름이 아니라 Google의 별도 오픈 모델군이다. 1차는 Google API로 사용하며, PC에서 직접 실행하는 Gemma는 설치·하드웨어·추론 서버 연결이 필요한 후속 기능으로 구분한다.

### 11.2 최신 모델을 계속 선택할 수 있는 방식

1. 연결 등록 시 실제 키로 제공자 모델 목록을 조회한다. 페이지네이션을 끝까지 처리한다.
2. ‘모델 목록 새로고침’ 버튼과 마지막 확인 시간을 표시한다. 연결별 목록 캐시는 24시간을 기준으로 갱신하며 요청 실패 시 기존 선택을 보존한다.
3. 모델 ID의 숫자를 문자열 정렬해 최신이라고 판단하지 않는다. 제공자 메타정보와 공식 목록에서 확인된 출시·상태 정보를 사용한다. 정보가 불충분하면 ‘최신’ 배지를 붙이지 않는다.
4. 텍스트 편집 가능 모델만 기본 목록에 표시한다. 임베딩·음성·이미지 생성 전용 모델은 글 수정 메뉴에서 제외한다. 문서 작성용 Gemma와 EmbeddingGemma를 구분한다.
5. 안정판을 기본 추천하고 프리뷰/실험 모델은 별도로 표시한다. 원하는 모델 ID 직접 입력도 허용하되 연결 시험을 거친다.
6. 사용자가 선택한 모델은 고정한다. 새 모델 발견 시 알림과 선택지를 제공하고, 사용 중인 문서를 자동으로 더 비싼 모델로 전환하지 않는다.
7. ‘최신 권장 모델 사용’ 옵션은 사용자가 켠 경우에만 동작한다. 검증된 추천 목록 안에서 요청 시작 전에 해석하고 실제 호출 모델을 표시한다. 제공자가 별칭의 내부 대상을 바꾸는 경우까지 앱이 고정할 수 있다고 설명하지 않는다.
8. 모델 사용 중단·권한 오류는 선택 변경 안내로 처리한다. 다른 모델로 몰래 재호출하지 않는다.
9. 지원 기능은 모델별 capability로 관리한다. system instruction, structured output, thinking/reasoning, output limit 등 지원하지 않는 매개변수는 보내지 않는다.

### 11.3 API·SDK 최신화 정책

- 현재 Gemini 코드의 레거시 `@google/generative-ai` 사용을 권장 `@google/genai`로 이전한다. 스트리밍·취소·오류·결과 정제·문서 가져오기 포맷팅의 회귀 시험을 포함한다.
- OpenAI는 Responses API를 기본으로 구현한다. 호환 서버용 Chat Completions 연결은 별도 전송 방식으로 구분하고 OpenAI 직접 연결과 섞지 않는다.
- Claude는 Messages API를 사용한다. API 버전 헤더와 베타 기능 플래그는 공식 지원 계약을 확인해 명시하며, 모델 버전과 API 계약 버전을 별도로 관리한다.
- ‘API 최신화’와 ‘모델 목록 갱신’을 구분한다. 새로운 모델 ID는 조회로 추가할 수 있지만 API 스키마나 스트림 형식의 변경은 어댑터 수정·검증·배포가 필요하다.
- 구현 시작일에 공식 SDK 최신 안정판과 런타임 호환성을 확인해 lockfile에 정확한 버전을 고정한다. 실행할 때 패키지를 자동 업데이트하지 않는다.
- SDK 변경은 의존성 업데이트 절차에서 계약 시험·보안 점검·웹/데스크톱 회귀 검증을 통과시킨 뒤 배포한다.
- 공식 모델/업데이트/지원 중단 안내를 출시 전 검토하고 계획서의 확인일·후보 목록을 갱신한다. 이 계획은 예약 모니터링이나 자동 업데이트 작업을 생성하지 않는다.

### 11.4 추가 수용 기준

- Gemini와 Gemma를 Google 설정 안에서 각각 선택하고 문서보기에서 동일하게 교정·교체할 수 있다.
- OpenAI와 Claude도 별도 모달 없이 같은 검토·적용 흐름을 사용한다.
- 테스트는 Google/Gemini, Google/Gemma, OpenAI, Claude 네 경로를 각각 검증한다.
- 새 모델 목록 갱신, 모델 삭제/권한 변경, 프리뷰 모델, 미지원 옵션, 비용 정책이 바뀌어도 기존 선택과 원문을 보존한다.
- 실 API 키 없이 계약 테스트가 가능해야 하고, 출시 전 사용자가 연결한 키로 각 경로의 소량 실호출을 검증한다. 이번 계획서 개정에서는 과금 API를 호출하지 않는다.

## 12. 온리비 AI 버튼 상·하단 분리 동작

사용자가 첨부한 두 줄 버튼을 기본 AI 진입점으로 한다. 일반 서식 플로팅 툴바를 열지 않아도 동작한다.

### 위쪽: 온리비 AI → 프롬프트 입력

- 위쪽 영역은 독립된 버튼이며 접근성 이름은 ‘온리비 AI 요청 입력’이다.
- 클릭하면 문서보기 안에 작은 프롬프트 입력 패널이 열린다. 별도의 전체 화면 모달은 열지 않는다.
- 클릭 직전에 유지된 선택 영역 또는 현재 커서를 대상으로 캡처한다. 버튼 클릭으로 선택이 사라져도 원래 대상을 보존한다.
- 선택이 있으면 ‘선택한 글 수정’, 선택이 없으면 ‘현재 문단 수정’, 빈 문단이면 ‘여기에 작성’을 기본으로 표시한다. 대상 범위를 명확히 보여준다.
- 입력란과 교정·요약·번역 등의 작업 선택, 실행/중지를 제공한다. 위쪽 클릭만으로 API 요청·과금이 발생하지 않는다.
- 이미 입력 중인 프롬프트가 있으면 다시 열 때 보존한다. Escape로 닫을 때 원문은 바꾸지 않는다.
- 생성 결과와 적용 버튼은 기존 계획대로 해당 구문 근처에서 제공한다.

### 아래쪽: 현재 모델명 ▾ → 제공자·모델 변경

- 아래쪽 영역은 위쪽과 별개의 버튼이며 접근성 이름은 ‘AI 제공자 및 모델 선택’이다. 이벤트가 위쪽 버튼으로 전파되지 않는다.
- 클릭하면 가까운 위치에 모델 선택 메뉴를 연다. 위쪽 프롬프트 패널을 함께 열거나 요청을 실행하지 않는다.
- Google → Gemini / Gemma, OpenAI → GPT, Anthropic → Claude로 구분한다.
- 현재 모델 표시·검색·모델 목록 새로고침·연결 설정 이동을 제공한다. 키가 없는 제공자는 ‘연결 필요’로 표시한다.
- 선택 즉시 아래쪽 모델명을 갱신한다. 긴 이름은 줄임표로 표시하되 툴팁과 접근성 이름에는 전체 이름을 제공한다.
- 프롬프트 입력 중 모델을 바꿔도 입력한 요청과 문서 대상은 유지한다.
- 생성 중에는 현재 요청 모델을 고정하고 모델 변경을 잠근다. 중지한 뒤 변경할 수 있게 안내한다.
- API 키 입력·연결 등록은 환경설정에서 관리한다. 모델 변경 메뉴에 비밀값을 노출하지 않는다.

### 편집기 연동과 검증

- 두 개의 형제 button을 사용한다. button 안에 button을 중첩하지 않는다.
- 편집기의 pointerdown 단계에서 선택·커서를 보존하되, 키보드 Tab/Enter/Space와 화면 읽기 접근을 막지 않는다.
- 메뉴를 닫거나 취소하면 원래 문서의 선택·포커스를 복원한다. 프롬프트 입력 시에는 패널로 포커스를 이동한다.
- 모델 메뉴와 프롬프트 패널은 하나씩만 열어 화면 겹침을 줄인다. 작성 중인 프롬프트는 메뉴 전환으로 삭제하지 않는다.
- 스크롤·배율·창 크기 변경에 맞춰 패널 위치를 갱신하고 인쇄/PDF에는 버튼·패널을 포함하지 않는다.
- 수용 기준: 위 클릭은 입력란만 열림, 아래 클릭은 모델 메뉴만 열림, 모델 선택 시 API 미호출, 선택 본문 보존, 프롬프트 유지, 생성 중 변경 차단, 키보드 접근, 탭 전환 시 대상 무효화가 모두 통과해야 한다.

이 절은 앞 절의 일반 진입점 설명보다 우선한다. 현재 변경은 구현계획서에 대한 요구사항 반영이며 버튼 기능 구현 완료를 의미하지 않는다.

## 13. 질의 첨부파일 및 프롬프트 템플릿 저장·재사용

### 13.1 요구사항과 기존 기능 이전

- 온리비 AI 버튼 위쪽으로 연 프롬프트 입력란에서 파일 첨부, 템플릿 불러오기, 현재 프롬프트 저장을 제공한다. 별도 AI 작성 모달로 돌아갈 필요가 없어야 한다.
- 현재 AIDraftModal에는 텍스트 파일 1개를 FileReader.readAsText로 읽는 기능과 리소스의 ai_presets.json 저장·불러오기가 있다. 해당 UI를 그대로 복사하지 않고 공통 서비스와 컴포넌트로 분리한다.
- 기존 ai_presets.json과 도메인별 프롬프트 템플릿을 먼저 인식한다. 사용자가 사용하던 내용을 초기화하거나 새 라이브러리로 숨기지 않는다.
- 이 절은 1차 출시 수용 조건에 포함한다. 기존 메인 구현과 함께 적용하며 이 계획서 개정 자체는 실행 가능한 기능 구현 완료를 의미하지 않는다.

### 13.2 입력란 구성

- 상단: 작업 대상과 현재 모델.
- 본문: 직접 요청 입력, 선택한 템플릿의 변수 입력.
- 첨부 영역: ‘파일 첨부’ 버튼, 드래그 앤 드롭, 준비된 파일 카드.
- 하단: ‘템플릿 불러오기’, ‘템플릿으로 저장’, 실행/중지.
- 파일 카드에는 파일명·크기·처리 상태(읽는 중/준비됨/지원 불가/오류)·제거 버튼을 표시한다.
- 모델 변경 후에도 프롬프트·변수 입력·첨부 목록은 유지한다. 새 모델에서 사용할 수 없는 첨부는 경고하고 전송하지 않는다.

### 13.3 첨부 형식과 초기 제한

| 파일 | 1차 처리 | 제한·안내 |
|---|---|---|
| TXT·MD·CSV·JSON | 텍스트 읽기 후 자료로 전달 | 인코딩 오류·빈 파일·바이너리 위장 검사. CSV 수식과 JSON 내용을 실행하지 않음 |
| PDF | 텍스트 추출 후 전달 | 스캔본·암호화·텍스트 추출 실패를 안내. OCR 자동 지원은 별도 범위 |
| DOCX | 기존 가져오기 계층을 활용해 텍스트/표 추출 | 원본 레이아웃과 이미지 분석을 보장하지 않음 |
| PNG·JPG·WebP | 선택 모델이 이미지 입력을 지원할 때만 전달 | 파일 서명·해상도·MIME 검사. 텍스트 전용 모델에는 보내지 않음 |
| HWP·HWPX·XLSX·PPTX·오디오·동영상·압축파일 | 초기 첨부에서는 미지원 안내 | 문서 가져오기 지원과 AI 첨부 지원을 혼동하지 않도록 구분 |

초기 앱 제한 제안은 최대 5개, 파일당 10MB, 합계 20MB다. 제공자 제한이 더 작으면 작은 한도를 적용한다. 추출 텍스트와 이미지 토큰을 문맥 한도에 합산한다. 단순 파일 크기만으로 전송 가능 여부를 판단하지 않는다.

- 파일 선택·내용 추출만으로 모델 호출이나 유료 AI 변환을 실행하지 않는다. 실행 버튼을 누를 때 전송한다.
- 첨부파일 파싱에 기존 가져오기 기능을 쓰더라도 원고 탭 생성, 이미지 리소스 저장, AI 포맷팅 등 부작용은 비활성화한 순수 추출 경로를 분리한다.
- 텍스트 추출 결과와 전송 분량을 확인할 수 있게 한다. 초과한 내용을 임의로 잘라 보내지 않고 파일 제거·범위 축소를 안내한다.
- 이미지와 모델의 파일 입력 지원 여부를 capability로 확인한다. 제공자 이름만 보고 동일 기능을 보장하지 않는다.
- 첨부 내용은 사용자의 지시와 구분된 자료 영역으로 전달한다. 문서 안의 명령을 앱 동작 지시로 실행하지 않는다.
- 원본 첨부파일은 질의 세션 메모리에만 유지하는 것이 기본이다. 원고 본문·메타정보·템플릿에 바이너리를 넣지 않는다.
- 공급사 파일 업로드가 필요한 경로는 공급사·전송 범위를 표시하고 임시 업로드 수명 및 삭제 정책을 명시한다. 삭제 실패는 재시도 또는 사용자 안내로 처리하며 즉시 삭제를 보장하지 않는다.
- 첨부 자체가 자동으로 출처 검증을 완료하는 것은 아니다. 파일명과 확인 가능한 페이지 정보는 근거 표시로 쓸 수 있으나 추출하지 못한 페이지 번호를 만들어 넣지 않는다.

### 13.4 템플릿 관리와 재사용

- 현재 입력 프롬프트를 이름·폴더·설명과 함께 저장한다.
- 목록 검색·불러오기·수정 저장·다른 이름으로 저장·복제·이름 변경·삭제를 지원한다.
- 동일한 이름이 있어도 조용히 덮어쓰지 않는다. 기존 항목 수정 여부를 명시하고 템플릿 ID로 저장 대상을 식별한다.
- 템플릿 선택은 입력란을 채우기만 한다. 곧바로 AI를 호출하거나 본문을 바꾸지 않는다. 작성 중 입력을 교체할 때에는 변경 내용을 보존하거나 확인한다.
- 기본 템플릿 예: 문장 교정, 쉽게 풀어쓰기, 강의자료 구성, 회의록 정리, 첨부자료 비교, 서류 준비 체크리스트 초안.
- {{대상독자}}, {{문체}}, {{출력형식}} 등 이름 있는 변수를 지원하고 실행 전에 누락 값을 확인한다. 치환은 데이터 삽입만 수행하고 코드·표현식을 실행하지 않는다.
- 저장 항목: schemaVersion, id, name, folder, description, prompt, variables, task, scopePreference, 선택적 provider/modelPreference, createdAt, updatedAt.
- 저장하지 않을 항목: API 키, 실제 선택 본문, 전체 문서 내용, 첨부 바이너리, 주민등록번호·계좌번호 등 질의별 데이터, 과거 생성 결과.
- 첨부 요구사항은 ‘비교할 자료 2개’ 같은 설명/슬롯으로 저장할 수 있다. 실제 파일은 질의할 때 다시 선택한다. 템플릿을 불러오며 PC 파일을 자동으로 읽지 않는다.
- 제공자·모델은 선택적 권장값이다. 다른 모델에서도 프롬프트를 재사용할 수 있고 권한 없는 모델로 자동 전환하지 않는다.

### 13.5 저장 위치와 기존 자료 호환

- 사용자 템플릿의 공통 저장소는 기존 리소스 폴더의 ai_presets.json을 재사용한다. 기존 도메인별 템플릿은 원본을 보존해 별도 범주로 함께 표시한다.
- 기존 editorialCommand, targetScope 및 systemPrompt/userPrompt 형식을 공통 템플릿 구조로 읽는 이전 어댑터를 제공한다. 화면에서 읽는 것만으로 파일을 다시 쓰지 않는다.
- 최초 수정 저장 시 기존 알 수 없는 필드를 보존하고 버전 정보를 추가한다. 원본 백업을 만든 뒤 검증된 결과를 원자적으로 교체한다. 웹/Drive에서는 사용 가능한 저장 기능과 충돌 검사로 이에 준하는 실패 복구를 제공한다.
- 리소스 폴더가 연결되지 않았으면 현재 프롬프트 사용은 허용하되 ‘템플릿 저장에는 리소스 연결 필요’를 안내한다.
- 폴더/계정 변경 시 캐시를 구분하고 이전 저장소의 템플릿을 새 폴더에 자동으로 쓰지 않는다.
- Drive/다른 창에서 동시에 수정된 경우 버전·해시 또는 제공되는 리비전을 비교한다. 충돌 시 덮어쓰지 않고 다시 읽기·사본 저장을 제공한다.
- 최근 사용 템플릿 ID와 목록 정렬은 계정별 설정에 보관한다. API 키나 원문 데이터는 템플릿 동기화에 포함하지 않는다.

### 13.6 추가 구성요소 및 수용 시험

제안 파일: lib/ai/attachments.ts, lib/ai/attachmentExtractors.ts, lib/ai/promptTemplateRepository.ts, components/ai/AIAttachments.tsx, components/ai/AIPromptTemplates.tsx. 기존 AIDraftModal과 새 InlineAIComposer가 같은 저장소·추출 경로를 사용한다.

필수 시험:

1. 여러 파일 첨부·동일 파일 중복 선택·개별 제거·용량 초과·취소·읽기 실패·세션 종료 후 메모리/객체 URL 정리.
2. PDF/DOCX를 이진 문자열로 보내지 않고 추출된 자료로 전달. 스캔 PDF·빈 파일은 명확한 안내.
3. 모델 변경 시 프롬프트와 파일 유지, 미지원 첨부 전송 차단. 네 모델군의 입력 형식은 각각 검증.
4. 첨부한 내용이 원고에 자동 삽입되지 않고 생성 결과도 승인 전 원문을 변경하지 않음.
5. 기존 ai_presets.json과 도메인 템플릿 불러오기, 수정·복제·재시작 후 재사용, 손상 JSON과 쓰기 실패 복구.
6. 템플릿 변수 누락·중복 이름·이름 변경·삭제·리소스 변경·Drive 저장 충돌 처리.
7. 템플릿 저장 결과에 API 키·선택 원문·첨부파일 바이트가 없는지 검사.
8. 템플릿 선택/저장/파일 첨부만으로 AI 호출이 발생하지 않고 사용자가 실행할 때만 호출.

## 14. 1차 구현 결과 및 검증 (2026-10-20)

### 소스에 반영한 항목

- 온리비 AI 두 줄 버튼: 위쪽 입력 패널 / 아래쪽 제공자·모델 메뉴.
- Google(Gemini/Gemma), OpenAI Responses, Claude Messages의 공통 공식 REST 어댑터와 스트리밍·중지·실패 처리.
- 모델 목록 조회·검색·직접 ID 입력·수동 새로고침·하루 지난 목록 재조회. 모델 자동 대체 없음.
- 문서보기와 마크다운 편집기 대상 캡처·추적·무효화, 원문/수정안 비교, 일반 텍스트 교체·일반 문단 추가, 한 번에 실행 취소.
- TXT/MD/CSV/JSON/PDF/DOCX 및 이미지 첨부. 순수 추출 경로를 사용해 원고 가져오기나 AI 포맷팅을 자동 실행하지 않음.
- 기존 프롬프트 라이브러리와 도메인 템플릿 조회, 사용자 템플릿 저장·복제·수정·삭제·변수 치환. 원본 백업과 저장 전 변경 확인.
- 웹 세션 메모리 키, 인증된 동일 출처 중계 API, 데스크톱 OS 암호화 키 보관·세션 연결·연결 해제.

### 구현 방식과 전환 상태

이번 공통 계층은 Google GenAI SDK를 새로 설치하는 대신 공식 REST API를 직접 사용한다. 제공자별 SDK에 결합하지 않고 웹 서버와 Electron에서 동일 프로토콜 코드를 재사용하기 위한 선택이다. 따라서 앞 절의 SDK 교체 계획과 달리 기존 고급 작성창·문서 가져오기 포맷팅용 Gemini SDK는 아직 그대로 유지한다. 기존 키를 새 영구 보관소로 자동 이전하거나 기존 키 설정을 삭제하지 않는다.

실제 요청은 완료 신호를 확인한 뒤에만 적용 가능하다. 스트림이 끊기거나 출력 한도에 도달하면 결과를 원문에 반영하지 않는다. 마크다운 구조 생성·표 편집·복합 서식 보존·지식보관함 자동 인용·Gemma 로컬 실행은 후속 범위다.

### 검증

- `scripts/check-inline-ai.cjs`: 세 제공자 스트리밍 계약, Google/Gemma 분류, UTF-8 분할 응답, 미완료 차단, 웹 인증 경로, 데스크톱 IPC·키 저장 계약·중지·패키징 목록, 입력창 버튼 동작, 첨부, 검토/적용/실행 취소, 기존 템플릿 UI 저장/재사용·충돌 차단.
- 실제 PDF·DOCX·PNG 첨부의 내용 추출 시험 포함.
- `scripts/check-visual-editor.cjs --visual --inline-ai-only`: 실제 문서보기 컴포넌트에서 대상 연결, 원고 동기화, 이미지·아래 본문 보존, 실행 취소, 변경 대상 차단.
- TypeScript 및 Electron JavaScript 문법 검사.

검증용 키와 모의 공급사 응답을 사용했다. 실제 사용자 키의 접근 권한·요금·할당량·운영 서버 환경변수는 자동 검증으로 확인하지 않는다. 웹 배포와 설치 패키지 빌드는 수행하지 않았다.

사용 방법과 배포 준비사항은 `docs/guides/문서보기-AI-사용안내.md`를 참고한다.
