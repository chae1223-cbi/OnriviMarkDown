# 내보내기 분석 및 개선 방안

작성일: 2026-10-03

## 1. 결론과 범위

현재 내보내기는 미리보기 DOM을 복제하여 형식별로 변환한다. PDF·HTML·PNG는 화면 서식을 비교적 직접 활용하지만, DOCX는 별도의 고정 서식으로 재구성한다. EPUB는 별도의 CSS와 XHTML 정리를 적용한다. 따라서 형식 간 차이를 CSS 수정만으로 해결하기 어렵다.

가장 먼저 미리보기 준비 상태와 미디어 누락을 확인하는 공통 절차를 도입하고, Word의 서식·구조 매핑, EPUB의 목차·링크·내장 리소스를 개선하는 순서가 적절하다.

최초 분석 대상으로 현재 소스와 기존 `02_온리비_환경_설정.html`, `02_온리비_환경_설정.docx`의 구조를 읽었다. 이후 사용자 진행 요청에 따라 1단계 구현을 반영했다. 두 파일이 같은 시점의 같은 원문에서 생성됐는지는 확인하지 못했다. PDF 실제 페이지 렌더링, Word 앱 화면 비교, EPUB 리더기 실행 및 EPUBCheck 검증은 이번에 수행하지 않았다. 해당 이름의 EPUB 샘플은 현재 다운로드 폴더에서 찾지 못했다.

## 2. 현재 흐름

| 형식 | 주요 처리 | 현재 특징 |
| --- | --- | --- |
| HTML | DOM 복제, 이미지 인라인 변환, CSS 수집, HTML 생성 | 외부 폰트·KaTeX CSS·Tailwind 스크립트 의존 |
| PDF | 인쇄 HTML 생성 후 Electron printToPDF 또는 웹 iframe 인쇄 | 플랫폼별 리소스 준비와 인쇄 완료 판단이 다름 |
| DOCX | DOM 순회, DrawingML 이미지, OOXML ZIP 직접 생성 | 맑은 고딕·A4·고정 여백·고정 제목 스타일을 기본으로 사용 |
| EPUB | 이미지 동봉, XHTML 정리, 본문 분할, OPF·목차 생성 | 별도 CSS 및 링크 변환, 외부 폰트 import 사용 |
| PNG | DOM 복제 후 html-to-image로 전체 높이 캡처 | 긴 문서를 단일 2배율 이미지로 생성 |

주요 코드: `frontend/src/lib/exportHandlers.ts`, `docxGenerator.ts`, `epubGenerator.ts`, `exportMediaHelper.ts`, `frontend/src/hooks/useEditorHandlers.ts`, `main.js`.

## 3. 확인한 문제와 개선안

P0은 내용 누락 및 작업 실패 방지, P1은 주요 품질과 기능 보존, P2는 사용성과 성능 개선이다. 코드로 확인한 처리와 실제 파일에서 확인한 사실을 구분한다.

| 번호 | 우선순위 | 확인 사항과 근거 | 개선안 |
| --- | --- | --- | --- |
| EXP-01 | P0 | DOCX 이미지 변환 실패는 null을 반환하고, 추출기는 성공한 이미지만 추가한다. EPUB 이미지 동봉 실패도 로그만 남기고 계속한다. HTML 이미지 인라인 처리에도 실패 후 계속하는 경로가 있다. | 이미지별 성공·실패·제외 사유를 수집한다. 필수 이미지 누락 시 완료로 표시하지 않고 재시도 또는 누락을 확인한 저장 선택을 제공한다. |
| EXP-02 | P0 | PDF·PNG에만 IME 확정 함수가 있다. 미리보기 복제 전 모든 형식에서 최신 편집 내용과 렌더링 완료를 확인하는 공통 절차가 없다. | 입력 확정 → 편집 내용 반영 확인 → 미리보기 렌더링·Mermaid·이미지 준비 확인 → 스냅샷 생성으로 통일한다. 마지막 한글 글자·다이어그램 누락을 검증한다. |
| EXP-03 | P0 | `imgElementToPng`는 data/blob 이미지의 원본 바이트를 바로 반환할 수 있지만 DOCX에서는 항상 `.png`와 image/png로 패키징한다. 원본이 JPEG 등일 때 형식 불일치 위험이 있다. | 원본 MIME·확장자를 유지하거나 실제 PNG로 변환한다. 파일 서명과 Content Types 일치 검증을 추가한다. 현재 샘플 8개 이미지는 모두 PNG 서명으로, 이 위험이 샘플에서 재현된 것은 아니다. |
| EXP-04 | P1 | Word 호출은 activeProfile·페이지 설정을 전달하지 않는다. 생성기는 기본 폰트, 제목 크기·색상, A4와 1인치 여백을 고정한다. | 공통 프로필을 DOCX 옵션에 전달하고 폰트·글자 크기·행간·정렬·여백·용지·방향·제목·표 스타일을 Word 단위로 매핑한다. |
| EXP-05 | P1 | DOCX 목록은 `•` 또는 `1. ` 등을 일반 텍스트로 넣는다. 시작 번호·중첩 수준을 Word 목록 구조로 저장하지 않는다. | numbering.xml과 numPr를 생성하여 목록 계층, 시작 번호, 번호 이어가기 및 재시작을 보존한다. 체크박스는 정적 기호와 편집 가능한 컨트롤 중 정책을 정한다. |
| EXP-06 | P1 | DOCX 링크는 파란색·밑줄만 적용하며 실제 하이퍼링크 관계를 만들지 않는다. 표는 셀별 인라인 내용을 한 문단으로 만들고 colspan·rowspan 구조를 매핑하지 않는다. | 외부 링크 relationship, 내부 bookmark/hyperlink, 셀 병합 gridSpan/vMerge와 셀 내부 문단·목록·이미지 지원을 구현한다. 중첩 표는 직접 자식 행만 순회한다. |
| EXP-07 | P1 | DOCX에 수식 네임스페이스는 있지만 OMML 변환이나 Word 각주 생성 경로는 확인되지 않았다. | 수식은 MathML→OMML 또는 명시적인 이미지 변환 정책을 적용한다. 각주는 footnotes.xml과 참조 구조로 매핑한다. 현재 일반 텍스트로 평탄화될 가능성은 별도 시험으로 확인한다. |
| EXP-08 | P1 | Electron PDF는 loadFile 후 800ms만 추가 대기한다. 웹 PDF는 문서 작성 후 onload를 등록해 이벤트를 놓칠 위험이 있으며, 무제한 대기와 고정 1초 iframe 제거가 있다. | 이벤트를 로드 전에 등록하고 폰트·이미지 decode 완료를 제한 시간 내 확인한다. 인쇄 준비 실패를 안내하고 afterprint 및 정리 절차를 적용한다. 웹에서는 인쇄창 호출과 실제 저장 완료를 구분한다. |
| EXP-09 | P1 | HTML에 외부 CSS·웹 폰트·Tailwind CDN 스크립트를 넣는다. 브라우저 환경에서는 외부 http 이미지 인라인 변환도 건너뛴다. | 공유용 HTML은 필요한 CSS·허용된 폰트·이미지를 내장하고 온라인 의존 항목을 진단한다. 앱 경로와 임시 blob URL이 남지 않았는지 검사한다. |
| EXP-10 | P1 | EPUB 호출은 제목별 분할 수준을 항상 none으로 전달하고 목차는 section 단위다. 수동 페이지 나누기가 없는 문서는 목차가 단일 항목이 될 수 있다. | 장 분할 설정과 h1~h6 기반 계층 목차를 분리한다. 파일별 헤딩 위치를 수집하여 `chapter.xhtml#heading-id`로 정확히 연결한다. |
| EXP-11 | P1 | EPUB의 .md 링크를 같은 문서의 해시로 바꾸지만 대상 문서를 함께 내보내는 구조는 없다. 첫 헤딩의 기존 id도 문서 id로 덮어쓴다. | 기존 헤딩 id를 보존한다. 함께 내보내는 문서만 링크를 매핑하고, 포함되지 않은 문서 링크는 미지원 항목으로 안내한다. 한글 제목도 충돌 없는 고유 id를 사용한다. |
| EXP-12 | P1 | EPUB는 외부 Google Fonts import를 사용한다. 데이터 URI는 모두 base64라고 가정한다. 외부 이미지의 5초 제한은 응답 헤더 수신 후 해제된다. | 허용된 폰트를 패키지 내부에 넣고 manifest를 작성한다. 이미지 MIME·파일 서명·URI 인코딩을 검증하고 본문 다운로드까지 시간 제한을 유지한다. |
| EXP-13 | P2 | PNG는 전체 문서 높이를 pixelRatio 2로 한 번에 캡처한다. 제공하는 fontEmbedCSS는 KaTeX 규칙 중심이다. | 긴 문서 크기를 사전 계산하고 페이지별 PNG·ZIP 저장을 제공한다. 본문·코드·수식 폰트를 함께 확인하고 실패 시 생성한 임시 DOM을 정리한다. |
| EXP-14 | P2 | 내보내기 모달에는 진행·취소·중복 실행 방지가 없으며 Word 설명이 '완벽 호환'이다. | 준비·변환·검증·저장 상태와 중복 실행 방지를 제공한다. 형식별 유지되는 기능을 설명하고 확인 범위를 넘는 호환 보장 문구를 수정한다. |

## 4. 제공 파일의 구조 확인

| 항목 | HTML | DOCX | 해석 |
| --- | --- | --- | --- |
| 이미지 | 6개, 모두 PNG data URI | 패키지에 8개 | 개수가 다르지만 다이어그램 변환·생성 시점 차이 등의 원인은 추가 시각 비교가 필요 |
| 표 | 1개 | 1개 | 표의 존재는 확인했으나 셀 구조와 서식 일치는 미검증 |
| 제목 | h1~h6 합계 14개 | 제목별 비교 미수행 | 제목 문구·계층·스타일 대조를 회귀 검증에 포함 |
| 목록 | li 15개 | numPr 0개 | Word의 실제 목록 구조가 없는 점은 코드 분석과 일치 |
| 하이퍼링크 | 링크별 목적지 비교 미수행 | w:hyperlink 0개 | 링크 기능 보존은 별도 시험 필요 |
| 이미지 형식 | PNG data URI | `.png` 8개 모두 PNG 서명 | 이 샘플에는 이미지 확장자 불일치 없음 |
| 외부 스타일 | 폰트 및 KaTeX stylesheet 링크 3개 | 설치 폰트에 의존 | 오프라인 및 다른 PC에서의 서식 확인 필요 |

이 표만으로 내용 누락이나 화면 깨짐을 확정하지 않는다. 구조 확인과 실제 렌더링 비교를 함께 해야 한다.

## 5. 공통 개선 설계

### 내보내기 준비

`prepareExportDocument`에서 최신 본문, 적용한 서식 프로필, 제목·목록·표·각주·링크·미디어 목록과 렌더링 완료 상태를 한 번에 수집한다. 형식별로 서로 다른 시점의 미리보기를 읽지 않도록 한다.

### 미디어 처리

`resolveExportAssets`에서 로컬 파일·브라우저 handle·Google Drive·blob·data URI·외부 URL을 같은 결과 형식으로 처리한다. MIME, 바이너리, 크기, 대체 텍스트, 캡션, 성공 여부를 함께 반환한다. Google Drive 임시 URL을 결과 파일에 그대로 남기지 않고 인증된 다운로드로 실제 데이터를 확보한다. 같은 이미지의 중복 다운로드와 중복 패키징을 줄인다.

### 형식별 변환과 완료 판단

PDF·HTML·PNG는 화면 배치와 색상을 우선하고, DOCX는 편집 가능한 문서 구조와 프로필 매핑을 우선한다. EPUB는 작은 화면에서 다시 배치되는 본문과 탐색 기능을 우선한다. EPUB에서 PDF와 동일한 페이지 수나 위치를 완료 기준으로 삼지 않는다.

공통 결과는 완료·취소·실패와 경고 목록을 구분한다. 파일 생성과 저장을 나누고, 저장창 취소나 이미지 누락을 성공으로 표시하지 않는다. 외부 자료 수집 실패 시 빈 이미지가 포함된 결과를 조용히 내려받지 않는다.

## 6. 실행 순서와 완료 기준

### 1단계 내용 보존

EXP-01~03, EXP-08을 우선 진행한다. 공통 준비·미디어 처리와 PDF 준비 확인을 작은 변경으로 도입한다.

완료 기준: 마지막 편집 내용 반영, 모든 필수 이미지 포함, PNG/JPEG/SVG 형식 일치, 준비 실패·시간 초과·취소 안내, 기존 문서 무변경.

### 2단계 Word 품질

EXP-04~07을 진행한다. 공통 프로필 전달 후 네이티브 목록·링크·표·각주·수식 지원을 순서대로 추가한다.

완료 기준: 세로·가로·A4·A5·사용자 여백 반영, 중첩 목록과 시작 번호 유지, 병합 표·셀 내부 구조 보존, 링크 클릭, Word에서 복구 경고 없이 열림. 프로필 효과 중 구현하지 않은 항목은 명시한다.

### 3단계 EPUB와 공유 파일

EXP-09~14를 진행한다. EPUB 계층 목차·링크·내장 리소스를 우선하고 HTML 오프라인 공유와 PNG 페이지 분할을 추가한다.

완료 기준: EPUBCheck 오류 0개와 경고 검토, 내부 링크 목적지 존재, 오프라인에서 이미지·허용된 폰트 표시, 대표 리더기 화면에서 큰 표·그림·한글 가독성 확인, 긴 PNG 문서 저장 성공. EPUBCheck는 EPUB 규격 적합성을 확인하는 공식 검사 도구이며 시각적 품질 검사를 대신하지 않는다.

## 7. 검증 계획

- 공통 기준 문서: 제목 h1~h6, 한글·영문, 굵게·기울임·취소선, 중첩 목록, 체크박스, 외부·내부 링크, 각주, 코드, 수식, 병합 표, 긴 표, 이미지, Mermaid, 지도·영상 대체 표현.
- 저장소: Electron 로컬, 웹 로컬 폴더, Google Drive. 데이터 URI PNG/JPEG, blob, 접근 불가 이미지와 인증 만료를 포함한다.
- 분량: 짧은 문서, 여러 페이지 문서, 페이지보다 큰 표·이미지·코드, 긴 전체 캡처 문서.
- 프로필: 기본 서식, 사용자 폰트·색상·테두리, 가로 방향과 사용자 여백, 오프라인.
- 자동 검사: 텍스트·제목·이미지·표 개수와 순서, 이미지 파일 서명, OOXML 관계·목록·표 병합, EPUB manifest·앵커·링크 참조.
- 시각 검사: 동일 원문의 HTML과 PDF 페이지, Word 화면, EPUB 리더기 화면 비교. 구조 검사와 실제 렌더링 결과를 모두 남긴다.
- 대상 앱: 실제 지원할 Word·Google Docs·EPUB 리더기와 브라우저 버전을 정하고 그 범위에서 검증한다.
